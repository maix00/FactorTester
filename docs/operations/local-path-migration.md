# 本机 TradeResearch 目录迁移

CLI 与桌面客户端共用一套目录选择规则：全新安装使用 `~/.traderesearch` 和 `~/Documents/TradeResearch`；旧目录仍是唯一现存目录时继续使用它。两套目录都存在且不是同一个目录时拒绝操作，避免静默切换工作区或登录态；显式 `TRADERESEARCH_HOME` / `TRADERESEARCH_CONFIG` 仍由调用者自行指定。Windows 上 `~` 为当前用户目录。当前运行中的旧数据没有被自动移动。

迁移工具是 `traderesearch client local-paths`。先关闭桌面客户端、后台使用相关目录的进程以及其他 CLI；`--quiesced` 是操作者的声明，并非跨进程锁，工具无法证明其他程序已停止。受 macOS Documents 隐私保护或 Windows 权限约束时，应先通过系统正常授权，不能绕过。执行前另行备份用户数据并确认可恢复。

对 `cli` 与 `documents` 分别运行 `plan --kind <kind>`。结果只包含路径、文件数量、大小和路径元数据摘要，不读取或输出 Cookie、会话或文件内容。检查现有目录、冲突和计划摘要；调用 `apply --kind <kind> --plan-sha256 <sha256> --receipt <受保护的目录外回执> --quiesced`。工具再次扫描核对，并使用操作系统的原子、禁止覆盖重命名：不复制数据，不覆盖已有目标；原 inode 和文件权限保持不变。旧目录保留为临时链接，以使尚未迁移的工作副本与 Git worktree 绝对引用继续可用。Windows 若系统不允许创建目录符号链接，操作会回滚并报错，不能静默复制或跳过。

回执记录操作意图、原目录身份及完成状态，不包含密码或密钥；它必须放在两个迁移根之外。POSIX 系统要求回执为当前用户拥有的私有文件；Windows 的权限由目标目录 ACL 继承，须选择当前用户专用目录。执行中断后，关闭使用目录的程序并用 `recover --receipt <回执> --quiesced` 恢复链接或中断的回退。已完成的操作可用 `rollback --receipt <回执> --quiesced` 将同一目录移回原位，并暂留新路径链接。目录身份或链接发生漂移时拒绝继续，需人工核对，不能删除冲突目标。

macOS 原有安全范围书签仍通过系统 API 检查与启用；新旧路径指向同一目录时，客户端对同一目录及不存在叶子路径按解析后的真实位置核对，越出授权根的链接仍被拒绝。书签失效或系统拒绝访问时需重新选择目录并授权；目录迁移本身不能保证跨应用签名或系统隐私设置的授权继续有效。

本工具不会读取、复制或改写 macOS Keychain / Secure Enclave；既有服务和设备密钥标识暂时保持稳定以免设备身份失效。若将来确需替换这些标识，必须使用系统钥匙串授权与服务端设备重新绑定，单独审计并验证回退。只有 CLI、桌面版本、已登记 Git worktree 与书签均确认不再依赖旧路径后，才能另行审计并移除临时链接；链接存在不表示迁移已经完全清理。不要把不明文件、无法读取或路径冲突解释为可删除数据。
