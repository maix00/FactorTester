# 联邦 Manager 的机构和节点密钥绑定

公网 Manager 为每个机构保留至多一条内网 Manager 登记。离线不释放该登记；移机、停用或更换密钥都不是自动解除机构绑定的理由。这里检查的是 **Manager 身份**，与本机构中可以存在的多个用户、设备或计算节点不是同一对象。

## 权威和新登记

公网 Keycloak 的机构组通过 `tr_internal_manager_id` 指向稳定的 Manager ID；Manager 专属组通过 `tr_internal_manager_id` 和 `tr_organization_id` 指回同一机构，并使用 `tr_node_key_fingerprint` 固定节点 Ed25519 公钥的 SHA-256 指纹。公网接收端先验证节点签名，核对 Keycloak 的双向绑定和指纹，再在注册表锁内检查其他已登记的内网 Manager，包括离线记录。缺失、冲突、损坏或验证服务不可用均拒绝；公开 Manager 不得冒充第二台公网 Manager。热路径的成功核验使用最多五秒的有界缓存，显式管理操作重新核验而不使用缓存。

## 旧登记的显式迁移

没有机构绑定的旧登记仍可查询，但心跳不会替它认领机构或覆盖凭据。公网超级管理员须先完成旧记录、公钥和 Keycloak 机构的逐项核对，再调用 `POST /api/admin/federation/legacy-manager-binding`。此接口默认只读 dry-run，返回被审核记录的稳定摘要；写入请求须附上同一摘要、`server_id`、`organization_id`、`fingerprint` 和 `dry_run: false`。写入时再次校验当前超级管理员角色、Keycloak 双向绑定、登记的公钥及旧签名、摘要和机构冲突，只修改匹配记录的机构字段。旧签名即使已经过期也可证明当时的节点身份，但不会因此恢复它的在线路由。

先备份并校验 Keycloak 配置、联邦注册表和节点身份数据库；确认旧记录没有缺源码、冲突或不明身份，再应用。管理操作写入 `manager-organization-bind-intent` 与 `manager-organization-bind-applied` 审计；完全相同的请求可重试，补写中断后的完成记录，不会重复认领或改动其他字段。公网 Job 权威库此前若没有 `job_dispatch_audit`，首次应用会按现有审计基础设施创建该表；部署和回退方案须明确包含这一点。无计算容器的 Manager 也需要访问它自己的 Job 权威库。不要在日志或工单中记录路由令牌、用户凭据或节点私钥。

旧节点身份缺少签名、指纹不一致或机构身份无法确认时，保持未绑定并修复来源，不自动认领。具体两端的盘点、备份和执行回执需在各次部署中单独记录；本文件本身不代表已经改动任何真实 realm 或完成迁移。

## 密钥轮换

新的签名密钥不能靠心跳覆盖旧登记：必须审计旧指纹与新指纹，显式更新受信的节点身份和 Keycloak 指纹，并使两端一致后才恢复登记。切换期间认证失败是预期行为；旧密钥回退应有受保护的备份和明确授权。当前登记器支持核对既有身份与显式的节点身份轮换，但尚未提供将 Keycloak 修改和两端密钥切换打包成一个可恢复操作的管理流程；应先完成该流程，再声称生产环境已支持完整密钥轮换。
