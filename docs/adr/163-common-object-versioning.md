# ADR-163：跨领域通用对象版本与同步清单

- 状态：分阶段迁移
- 日期：2026-10-24

## 背景

因子家族源码、用户策略和产品组定义都需要可审计的历史版本，并会被 RunSpec、账户目录或其他对象引用。现有实现各自保存历史：因子家族用公式指纹保存源码快照，用户策略用 revision UUID 与源码哈希保存源码，产品组只保留当前定义。跨服务器传输则都使用 Manager 的 account-domain outbox、cursor、冲突处理与对象数据面，但版本索引的字段与产品组历史缺少共同合同。

策略库还需要把平台内置公共策略与用户编写的 Nautilus 策略源码分开。目录的三个顶层范围是公共策略、我的自定义策略、下级自定义策略；`private/shared/public` 是用户自定义策略的可见性设置，不替代这三个目录范围。

## 决策

1. 以 `versioned_object_revision` 作为跨领域的不可变版本索引实体。每条记录包含 `object_kind`、稳定 `object_ref`、不可变 `revision_ref`、内容 SHA-256、所有者、创建者/时间、可见性、字节来源 Manager 和来源实体类型。对象身份与版本身份组成稳定、有界的同步键。
2. 版本索引经现有 account-domain 同步通道传播；不建立第二套 outbox、游标或冲突协议。可见性和数据来源字段放在现有传输可识别的顶层。公共内容、本人内容及明确授权内容继续使用现有可见性策略。
3. 不把因子源码或用户策略源码复制进控制面元数据。源码仍由因子源码存储/策略修订存储拥有，并经现有 7997 对象数据面按哈希取回。RunSpec 只冻结精确的策略修订与所引用因子修订。
4. 产品组的每次语义定义变更保存一个含定义快照的不可变版本实体；排序、页面投影和更新时间不属于定义版本。删除当前产品组不删除它的历史版本。
5. 策略目录明确区分只读的公共因子策略模板、当前用户自定义 Nautilus 策略、直属下级用户自定义 Nautilus 策略。自定义策略的分享权限继续由既有策略权限模型决定。
6. 公共内置策略采用代码内固定 revision ref；用户自定义对象采用各自稳定修订引用。任何运行读取固定 revision，不在执行时解析“最新”。

## 当前实施边界

- 共用版本清单的构造、校验、账号域持久化与本地读取已在 `server/services/versioning/` 实现。
- 因子源码版本和用户策略修订开始发布共用版本清单；原有 `factor_source_version` 与 `strategy_revision` 行仍作为数据面发现/水合适配信息，不是新的版本权威。
- 产品组写入开始保存定义快照和共用版本清单；现有产品组数据无需生产 schema 迁移即可使用已有 account-domain 实体表。
- 策略库 UI/API 将公共模板、本人自定义和直属下级自定义分开显示。公共模板是只读配置模板，不是用户策略源码。
- 本 ADR 不表示所有旧历史记录已回填，也不表示版本比较/恢复 UI 已覆盖每个对象种类。回填只能使用可验证的现存快照；不得伪造不存在的历史。
- 账户域同步的可见性规则仍是跨服务器授权边界。直属下级目录只有在当前主体能从本地目录或同步镜像合法读取其对象时才显示；不得通过放宽 `private` 或来源校验来补齐列表。

## 后续验收

- 同一 revision 在离线重试、重复同步和多 Manager 接收时保持同一身份与哈希；冲突不覆盖不可变版本。
- 版本索引跨服务器传播，源码仍按哈希从正确的来源节点水合；缺源码时明确显示未水合，不丢弃版本清单。
- 产品组定义快照在变更、重排、删除和跨服务器同步测试中保持正确；重排不制造定义版本。
- 公共模板不会与用户脚本混入同一写入/权限路径；下级范围严格按账户直属父子关系解析。
- RunSpec 固定策略修订和完整因子修订图；读取和重放不访问对象的当前版本指针。
