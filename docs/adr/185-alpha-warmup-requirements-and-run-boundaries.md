# ADR-185: alpha 预热需求与运行区间

状态：实施中（2026-10-27）。

真实原因子诊断暴露：任务成功不意味着内层250交易日阈值已就绪。184交易日
不能当成研报回测验收。不能把250d换算成250个自然日，不能只取嵌套窗口最大值。

alpha 负责数据无关的 DAG 需求分析，覆盖所有 Where/搜索依赖，CSE 节点仅走一次。
公开 warmup_requirements 输出历史 Bar（不含当前）、交易日、完整分区、信号形成
相位及未解决的 blocker。嵌套窗口沿依赖链相加，分支合并；混合单位保留。
摘要返回保守完整窗口上界。WarmupTimeline另提供冻结观测索引上的精确结构边界，
借用时间轴并缓存Rust信号映射，不复制价格面板；它不冒充数据值相关短路或NaN修复器。
存在Bar分区时返回canonical source ordinal，调用方须保持分段锚点。EMA须先给收敛策略，动态
截断缺上界时拒绝推导，未知节点不能当成0。alpha不导入平台Product/数据源。

数据源自身负责提供冻结版本下的覆盖范围、可用时刻和逐产品session统计，并
提供请求区间的字节；本次不修改正在解耦的sources实现、不建立第二套读取器。
required_history_start 只消费标准化(start,end,observed_count)元数据；不猜日历。
缺逐Bar索引时多读完整session，不虚构精确时间点。来源回放不得超过正式终点；
最后一个观测可以早于终点（休市/真实缺数），回执单列实际首末可用时刻，不猜休市日历。

TradeResearch的 factor_warmup 配置默认auto，custom允许显式更早数据起点。
disabled仅限diagnostic_only，报告不输出正式绩效。RunSpec固定策略版本/因子
引用和政策；执行在引擎创建前重建/校验需求与每来源覆盖，结果保存派生回执。
规划阶段仍需对接独立数据提供器，冻结解析后的需求/读取区间，不能宣称所有来源
都能自动补历史。配置schema已通过后端run_fields与审核fields输出；不修改前端。

一个共享Actor消费预热和正式行情；消费者在trading_start前不下单。只增加时间
比较，不维护第二套数值状态。报表使用Nautilus返回序列与统计类，按performance
窗口筛选；原始CSV保留完整审计。数据、允许交易、绩效区间分别记录。预热数据
不进入正式Sharpe/回撤；disabled的诊断报表不能被称为有效收益复现。

原研报的29个月连续主力/复权序列仍需要数据提供器正确对接；单一2512合约的
184天无法提供所需历史。不得把拼接的假连续合约或合成循环称为真实预热行情。


当前平台不裁剪已冻结的输入tape来改变预热：数据起点与scope锚点保持不变，
只校验覆盖并控制交易/绩效起点。custom是最早需要覆盖的读取要求，回执同时
记录requested与actual起点，不能声称实际只读取了custom以后的数据。数据源若
另行提供更短tape，必须保留canonical序号/分区锚点；不把它当作无影响的优化。
本轮日分区原因子已经用完整历史与足量后缀逐点比对正式信号和内层阈值。

2026-11-02 对本机 `main_mink/T.CFE.parquet`、`TL.CFE.parquet` 的
`trading_day` 列只读盘点：两个序列各 147,390 根 Bar、578 个交易日，均从
2024-01-02 开始，至 2026-05-27 结束。使用当前 250d 内层、20d 外层的
270 个完整交易日保守上界时，第 271 个交易日是 2025-02-19；这只是可能具备
完整预热的候选日，并非逐值有效性或实际交易验收。原样本内从 2024-01-02
开始，本机数据没有之前的分钟预热历史，不能把该时点当成窗口已完整的绩效
起点。若未找到更早的真实数据，须明确报告缺失、区分实际可评估区间和原
样本区间；不能合成价格或用日历天数替代交易日数。

同日用新编译的 alpha 扩展，对历史源码快照中 `SgChgPct(250d, M=0.6)` →
`SgChgDurDay` → `TsDurDevDayScope` → `TsHistCmp(20d)` 的新冻结定义做了
因子值诊断。T 和 TL 均读取上述 147,390 根 Bar；从 2025-07-01 起，各 1,862
个形成时点批量与增量值逐点一致；从 2024-04-02 后缀重放并绑定原始观测序号，
各 55,845 根正式区间 Bar 与完整历史重放一致。扩展 SHA-256 为
`a962b855ef6ae01deb94c2aece9aa7fd44afbc9afcad84b751a9ae4d008df97a`，
冻结诊断输入文件 SHA-256 为
`293730984051d718c26aca589c7091245fc542c290dc66b0ee06bf34ee08b0db`。
这是单次本机因子计算对照，不包含下单、换月、费用、数据加载或 Job 调度，
不证明历史 Job 的因子身份，也不能作为回测耗时或研报收益。

同日只读核对了上述两条连续序列与 `data_mink_product` 的实体合约分钟数据：
T、TL 各 147,390 条连续记录，分别涉及 11 个实体合约和 10 次主力切换；按
`contract_uid`、`trade_timestamp` 关联时，两者均没有缺失合约文件、缺失
对应记录、重复实体合约时间键或 OHLC 不一致的记录。每次切换时刻及其后的
下一根连续 Bar，旧、新两个合约都能找到对应分钟记录；2025-07-01 之后各有
4 次切换。这只说明当前文件具备匹配的价格记录，不能证明主力选择在当时可知、
成交容量、换月执行、费用、结算及冻结数据版本正确，更不能替代真实回测。

同次抽查实体合约 `T2403` 和 `TL2403` 的分钟文件：各 43 个交易日、各
10,965 条记录中，每个交易日的 `settlement_price` 在所有分钟上均是同一个
值，首个 09:31 记录即包含它。因此不能把每根分钟记录上的该字段当作当时
可用的结算事件；此现象提示可能存在日终值回填，但尚未核实供应方发布时间。
日结必须使用权威结算值及其可用时间，不能用日内提前暴露的字段制造未来信息。
