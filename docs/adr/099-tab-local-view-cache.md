# ADR-099: 标签页状态缓存与分级内存回收

## 状态

已接受。

## 背景

FactorTester 的页面会在多个 tab 之间切换。重新请求路由虽然能够恢复页面，
但会丢失表单输入、滚动位置、折叠状态和正在编辑的 overlay。另一方面，长期
保留每个 tab 的完整 DOM 会让产品树、任务表和报告附件持续占用浏览器内存。

## 决策

1. 每个 tab 的页面 DOM、工具栏和表单事件监听器先作为热视图放入
   `DocumentFragment`。返回同一 tab 时直接恢复，不重新请求页面。
2. 热视图最多保留三个。超过上限时，按最近使用时间将非活动 tab 冷化：释放其
   页面 DOM，只把路由元数据、滚动位置和可恢复控件状态写入
   `sessionStorage`。返回时重新渲染路由，再恢复这些状态。
3. 动态 overlay 记录所属 tab。切换 tab 时隐藏其 overlay；从 overlay 导航到
   另一页时强制打开目标 tab，不能把目标页绘制到 overlay 所属 tab 的背景中。
4. 打开的 overlay 暂时保留其 DOM 和事件监听器。这样可以准确恢复复杂的动态
   表单和操作行为；它们不进入冷快照，避免只保存 HTML 后丢失闭包事件处理器。
  用户关闭 overlay 后，节点由原有的 close 处理器释放。
5. 登录弹层是全局弹层，不绑定到业务 tab；报告设置等静态业务弹层绑定到
   创建时的活动 tab。

## 后果

- 普通页面和大型表格的内存占用受热视图上限约束；冷快照本身只保存小型控件
  状态，不复制页面 HTML。
- 冷化页面返回时会重新执行一次该路由的数据读取，因此如果服务器或数据源
  不可用，页面会显示原有错误，而不是伪造旧数据。
- 打开的复杂 overlay 以保留交互正确性为优先，直到关闭前仍占用其自身 DOM；
  这是无法在不重新绑定事件处理器的情况下安全序列化动态 overlay 的明确取舍。
