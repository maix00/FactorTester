# ADR 091：Swift 引导手动回退与研究对象 7997 数据面

## 状态

已接受

## 背景

Swift 客户端发布包必须带有至少一个可替换的公网引导地址，才能在用户没有预先配置
服务器时启动。但公网 IP、证书或网络状态可能变化；如果引导失败后仍直接进入 Web
shell，用户只能看到网络错误，无法输入新的 Manager 地址。

同时，研究报告的共享附件、嵌入图片和本地资源不应继续把文件内容塞进 7998 的 JSON
投影。已有对象数据面规定 7998 负责元数据和短时票据，7997 负责经过授权的字节流；
客户端和 Web shell 必须真正使用这条路径。

## 决策

1. Swift 每个发布构建只保留一个 `ManagerConfig.bakedPublicBootstrapEndpoint`。它是
   只读引导种子，不是用户身份、设备白名单或最终 Manager 地址。Manager 成功返回的
   在线目录仍负责后续公网节点选择；不在客户端硬编码全部公网 IP。
2. RootView 启动时先执行一次只读网络发现。自动引导、已保存的手动 Manager 或服务器
   返回的在线节点均不可达时，显示原生「连接 FactorTester」配置页；用户输入的地址
   先通过 `GET /api/server/network-info` 验证，再保存为手动 Manager。公网地址仍必须
   使用 HTTPS；这条流程不绕过登录和设备认证。
3. 手动首次连接只证明 Manager 可达，并进入 Web shell 的正常登录页。它不因为没有
   原生设备密钥而把首次启动错误地当成设备认证失败。
4. 研究对象下载统一为两阶段：客户端或 Web shell 先在当前 Manager 的 7998 请求
   `/api/transfers/objects/download-access`，再携带短时 bearer 访问授权 URL 的
   7997。附件、嵌入资源和 `research_local_resource` 都使用对象种类明确的票据；不
   允许回退到公开路径直接取字节。
5. 研究对象上传也采用同一边界：7998 校验研究所有权、大小和 SHA-256 并签发上传
   票据，字节通过 7997 PUT。Swift 上传完成后保留服务器返回的传输 ID 与对象摘要。
6. 7997 的浏览器请求不携带 Manager Cookie，只携带短时 bearer；Web shell 使用
   `credentials: "omit"` 和拒绝重定向。Swift 对下载结果检查授权声明的大小和
   SHA-256，Web shell 至少检查声明大小。源 Manager 离线时返回明确的对象不可用错误。
7. 本地 `local:` 研究仍可以使用本机 Manager 的本地路径；共享/公网研究对象必须走
   上述 7997 对象数据面。这样不改变 Swift 本地报告文件读取，同时避免跨 Manager
   读取绝对路径或旧的 7998 字节路由。

## 后果

- 引导公网 IP 暂时不可达时，用户可以继续配置新的 Manager，不需要重新安装客户端。
- Web、Swift、CLI 的共享研究附件遵守同一条控制面/数据面边界，跨 Manager 时由服务端
  既有对象适配器处理，客户端不接触 WireGuard 或 17997。
- 研究对象下载会多一次 7998 授权请求；这是权限、过期时间和跨节点路由的必要成本。
- 浏览器对象读取会把当前文件缓冲为 Blob 以创建临时 URL；大规模生成物仍使用已有的
  流式生成物/提交物下载器，不通过本报告对象读取器承载。
