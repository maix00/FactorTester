# ADR-161 — FactorTester 图表工作台与 Highcharts 渐进退出

状态：已接受（Issue #440，2026-10-20）。

## 决策

以 FactorTester 自己的因子—策略—交易—结果链路为工作台核心。React + TypeScript 是独立延迟挂载的界面边界，Lightweight Charts 只负责可交互绘图。FactorExpr、增量因子计算、Strategy Intent Policy、订单撮合和 Job/Run 结果继续是权威来源；浏览器不得用图表插件重新计算因子或盈亏，也不得把因子值当作可交易价格。

首阶段只 fork [TradingView Lightweight Charts](https://github.com/tradingview/lightweight-charts) 到 [maix00/lightweight-charts](https://github.com/maix00/lightweight-charts)，并以 `vendor/lightweight-charts` Git submodule 固定 v5.2.1 / `b2ce010e4ad59f6556c9ed60e2b2b30feccdd2d1`。官方 npm 同版本的 standalone 浏览器产物经固定 SHA-512 完整性校验后纳入 `static/vendor/lightweight-charts/`，构建和运行无需在生产主机下载依赖。Apache-2.0 `LICENSE`、`NOTICE` 随产物保存；启用图表时保留库自带的 TV 署名标识，不重复添加文字标注。两个社区指标/绘图仓库尚非纵向链路必需，不作为 submodule 引入；只有具体功能需要、API 与许可核查通过时再单独决策。

新工作台先挂接现有认证、路由及 Job 结果 API。K 线、FactorTester 计算的因子序列、策略信号、目标仓位、订单状态、成交、实际持仓、权益与回撤按同一时间轴展示；量纲不同时使用独立价格尺度或窗格。交易与盈亏只依据真实可交易合约的行情和既有执行规则。结果明细与 Job 生成物保留可审计来源，图表不持有权威状态。

## 渐进迁移

1. 建立独立 React/TypeScript 打包与按需挂载边界，先用产品行情页验证 K 线、成交量、持仓量及范围请求；证明 Manager 和 macOS 嵌入 Web 均可从本地静态资源加载；首屏不得因此预载图表库。
2. 以一条冻结因子曲线、一个策略规则和一个真实行情回测 Job 验证端到端数据合同。优先迁移交易图 Asset Plot，逐项覆盖 ADR-160 的行情源范围加载、原始频率、同刻多事件、订单生命周期、账本字段、价格线和缺失数据语义。Asset Plot 已在任务分支完成浏览器迁移验证；冻结因子曲线、策略规则及完整端到端合同仍须单独验收，不以合成浏览器数据代替真实 Job。
3. 将公共价格查看器、因子序列、IC 与其他 Job 图表逐个迁移；每个入口在数据/交互/性能验收通过后才移除对应的 Highcharts 脚本声明。因子序列的嵌套层级按同一因子与产品聚合，作为可开关的独立数值窗格与价格、成交量、持仓量共用时间轴；缺失因子值保留为空点，不用价格或相邻因子值补齐。旧因子序列 Highcharts 专用绘图模块在新入口验收后移除，通用 Job 生成物预览仍可继续使用 Highcharts。
4. 最后删除 Highcharts 共享适配器与静态资源。迁移前不能因新图表存在就删除旧资源。

交易图的范围选择、双向滚轮缩放与最小源频率均需保持。样本稠密时的绘制抽样不能删除事件锚点或改变成交/行情数值；未记录的 Level 2、保证金或订单阶段不得凭图表推断。旧图表是逐入口可回退路径，不做双份权威计算或结果存储。

2026-10-21 修订：产品与合约价格查看器改为由用户在设置中明确选择 K 线频率与时间范围。服务端只按选定的日历/交易日频率聚合原始 OHLCV；选“原始频率”时返回源 K 线。单次结果超过浏览器预算时提示缩短范围或选择更粗频率，不再悄悄切换聚合程度或截断蜡烛。所选结果作为一份固定数据交给 Lightweight Charts，滚轮缩放与范围选择不重新请求或替换序列，避免时间锚点因索引变化而漂移。切换设置时保留旧图并显示虚化加载状态，成功后一次替换。其他使用范围加载的 Job 图表仍保留各自数据合同与精确事件锚点。

补充：图表设置采用草稿与“保存并加载”，选项改变不请求数据；超出预算时保留草稿、旧图和具体根数，通过公共通知队列报错。“最近一天／一月／一年／今年以来”以所选数据源最后可用 K 线为基点，由服务端在该源内解析，不取浏览器当前日期。数据源继续声明独立的物理采样频率和 `delivery_mode`；默认是 `historical_snapshot`。只有源显式声明 `live_stream` 时才显示“实时”来源与 `LIVE` 图表频率入口。`LIVE` 读取该源的原始 bar，不把历史快照伪装成实时数据；实时推送、订阅与增量刷新须由将来实际接入的实时源实现并单独验收。

产品页“行情数据”默认加载所选日度源的全部历史。期限结构的每段起止日期在图表背景形成可复用的区间层；点击表格行只强调对应区间，当前视窗与该区间不相交时才移动视窗，不改变数据请求范围、K 线频率或可缩放的全历史。显式选择了不覆盖该区间的窄数据范围时，保留当前设置并提示扩大范围。

期限结构表的“数据”列由该合约在注册数据源目录中的可用源推导：先取得源描述，再去重展示各源声明的频率；没有可用源才显示“无数据”。界面不枚举 MIN1、DAY1 或未来的实时/Level 2 频率。LocalCNFutures 的合约日度期限结构快照作为正式 DAY1 数据源注册，其可用性由源自己的合约 UID 索引判断；图表读取该源时按源声明的 `contract_data_layout` 解码。新类型数据源需提供对应读取能力，不能仅因频率标签相同就套用日度快照解析。

## 验收与回退

逐入口核对同一 Job/合约/时间范围的源 bar、因子值、事件 ID、逐笔账本与策略/账户/资金池筛选结果；覆盖空值、历史 Job、乱序范围响应、移动端尺寸和 macOS 嵌入。记录冷/热加载体积与交互延迟，避免把 Node 合成数据误称为浏览器性能。未通过的入口保留 Highcharts；回退只恢复该入口的渲染选择，不修改 Job、数据库或因子结果。
