# ADR-133：IC 核心测试矩阵与类型化附加分析图

> **编号迁移说明：** 本文原文件名为 `066-typed-ic-core-matrix-and-analysis-graph.md`。因 ADR-066 已用于
> 容器化服务器运行时，本文迁移为 ADR-133；决策内容不因重编号改变。

- **状态**：已采纳
- **相关**：ADR-050、ADR-132、Issue #182

## 背景

IC 测试曾把因子、产品范围、前瞻收益期、Delay、统计方法、滚动窗口、
重采样、分期、分组组合和结果文件混在同一组扁平设置中。这种表示无法区分
“必须先计算的核心 IC”与“消费已有结果的附加分析”，也无法表达多个输入、
共享子结果或合法的下游依赖。客户端因而只能硬编码字段和兼容关系。

## 决策

IC 运行配置由三个正交对象组成：

1. **核心测试块**：显式声明产品范围、冻结因子、Horizon、入场 Delay、IC
   方法和收益定义。批量添加是有预览计数及上限的显式笛卡尔展开；展开后按
   内容地址去重，输入顺序不影响执行身份。
2. **附加分析图**：后端注册每种分析的输入类型、输出类型、目标基数、
   `map_each` / `combine`、参数和兼容轴。权威模型是无环图，界面只把它投影
   为可展开的树、Chip 和子行。每个可挂载分析同时注册自己的 Chip 描述（短
   标签、参数模板、参数来源和点击目标）；Web/Swift 只按 manifest 通用渲染，
   不得在客户端维护分析名称、中文标签或参数格式的第二份列表。
3. **输出请求**：表格、SVG、JSON、CSV 和保留策略只决定结果投影与持久化，
   不伪装成分析节点。

一个产品范围仍对应一个 Job；同一 Job 内复用因子值并执行因子 × Horizon ×
Delay × IC 方法矩阵。跨产品范围的组合必须成为显式派生 Job。RunSpec（界面
统一译为“运行配置”）冻结规范化后的核心单元、附加分析图和输出请求，不能
包含界面的聚合维度、展开状态、选择状态或排序。

Horizon 在作者配置中使用“基准 × 正整数倍数”表达，基准可以是因子自身信号
频率，也可以是显式物理频率。冻结时必须按每个因子的信号频率解析成 `MIN5`、
`DAY1` 等物理周期；核心矩阵和执行器只使用物理周期，不能把不同基准下相同的
`5×` 当成同一测试。运行配置同时保留作者表达及其解析映射；多个表达式若得到
同一物理周期，只执行一次，但保留全部来源供 Job 详情审计。

每个核心测试块拥有独立、内容寻址的作者请求；解析映射按“核心请求 → 因子”
保存，不能只按因子做全局合并，否则同一因子在不同核心块中的 Horizon 策略会
失去归属。加载冻结配置时必须用作者请求及解析映射重新展开核心矩阵，并核对
全部内容地址。旧扁平字段只能进入一次性迁移函数；正常 writer 只接受类型化
核心测试请求、类型化分析附件和输出请求，不保留扁平字段的隐式 fallback。

RunSpec 保存完整 IC 运行配置；每个 Job 的执行计划只引用该运行配置，并列出
本产品范围拥有的核心单元、依赖拓扑排序后的分析节点和输出请求。Job 详情复用
同一运行配置页面展示完整配置，同时单独显示当前 Job 的执行子集，不复制或改写
另一份配置。

通用设置注册表只提供领域 manifest 的挂载 seam，不理解 IC 图语义。Web、
Swift 嵌入页和 CLI 消费同一份后端 manifest；客户端可以提前过滤候选，但
服务端 planner 必须重新校验类型、基数、轴一致性、循环和执行能力。没有真实
executor 的分析或设置不得出现在能力 manifest 中。

分析候选的兼容结论也由后端注册合同生成，返回稳定的原因代码与详情；正式图
校验复用同一组规则，不能再由 Overlay 和执行规划器分别猜测。图模型允许分析
节点消费另一个分析节点的类型化输出，但只有对应 Job Adapter 接通后才能在能力
manifest 中注册；注册以前不得用客户端特判伪造下游能力。

一次附加分析操作必须先生成完整计划，再原子应用。`map_each` 为每个规范化后的
目标创建一个节点，`combine` 为整组选中目标创建一个节点；映射方式、参数默认值
和约束全部来自后端注册合同。选择中只要有一个目标不兼容，整批操作即被拒绝并
返回逐项原因，不能静默跳过。重复目标在计划中去重并记录原始重复数量；内容相同
的再次提交复用既有节点，因此不会产生重复计算或随点击顺序变化的执行身份。

## 迁移

- 旧的滚动 IC、分期、重采样、分组组合和持有期半衰期逐项迁移为注册分析；
- 旧扁平字段一次性编译为相同图，新的 writer 不再产生旧结构；
- `group_adjust`、`by_group`、`min_cross_section_count` 必须接入执行器或从
  manifest 删除，不能继续处于“可配置但不执行”状态；
- 数值迁移以代表性旧配置逐项一致为验收，不以页面看起来相似为准。

## 结果

新增分析只需注册一次，并由 planner、RunSpec、Overlay、Job 结果和报告输出
共同消费。核心矩阵可以单个或批量编辑，分析可以共享输入而不重复执行；界面
仍保持紧凑树形交互，但不会成为执行合同的权威来源。

当前审计确认 `group_adjust`、`by_group` 和 `min_cross_section_count` 没有 IC
执行消费者，因此从能力 manifest 与空结果页中删除。旧冻结前配置若显式启用
这些字段会被一次性编译器拒绝，不能静默产生与界面不一致的结果。
