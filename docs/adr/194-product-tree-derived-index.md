# ADR-194 — 产品树的有界派生索引与多源身份边界

状态：本机 Manager 性能切片已实现，#451；跨节点目录与 React 功能对等仍待验收。

## 事实与决策

原 contract-tree 无搜索只投影当前页，但每页重复排序/过滤；搜索每页投影全部产品的可用源和描述。源家族映射还通过包含全目录 availability/count 的描述投影取得，合约 has_data 再查一次源。DOM 虚拟化并不能消除这些服务端成本。

本机已解析的产品对象仍是权威运行时目录；新增 SQLite 文件仅是进程内临时派生缓存，不是用户数据库、源代码存储、市场数据副本或同步协议。第一次普通页仅投影当前页；第一次搜索构建该作用域的元数据索引；后续页复用排序、元数据和 casefold 文本。substring 语义保持，包括源成员名。排序用 name/path，去重用 canonical classifier path，不按展示名或产品 code 合并。重复提供同一产品不增加叶子数，不同路径的同名产品保持独立。

重复的 source_ids/source_family_ids 集合在 SQLite 中按集合内容共享存储，读回时重建独立响应，避免多源重叠让每个产品重复存储长来源列表。这个压缩只共享相同元数据数组，不解释或合并来源身份。来源家族映射直接读取注册成员归属，不再为每个产品触发完整目录 availability/count 投影；合约 has_data 使用同次来源结果。

源过滤树最多8个作用域、合计200,000对象引用；叶子索引最多8个作用域、合计200,000输入对象引用；使用[SQLite私有临时数据库](https://www.sqlite.org/inmemorydb.html#temporary_databases)（空文件名），连接关闭自动删除，不在用户目录留下具名缓存文件。SQLite文件上限128 MiB，SQLite页缓存2 MiB，不写WAL/回滚日志，不缓存任意查询结果。输入成员、路径和排序也有额外Python开销，上述数字不是进程RSS硬上限。元数据/来源集合不得无界增长；超限或投影失败清除派生索引并报错，绝不静默截断目录。临时数据库在显式失效及进程正常退出时关闭，由SQLite管理其临时文件生命周期；不建立可恢复的具名缓存目录。

作用域含目录 epoch、principal、明确的源集合（None与空集合不同）、分类和路径。分类成员仍通过当前主体重新解析，成员对象替换/删除会重建该叶子索引。Bundle inventory/注册表替换触发 epoch 失效；旧 base tree 替换使源过滤缓存失效。可用性是快照，不承诺随任意源文件变化实时刷新：认证用户显式“刷新产品目录”通过 `/api/product-library/tree?refresh=1` 清除本地 products/contracts/tree 与投影缓存，然后重新读取。访客不能用此参数使共享索引失效。无变化的分页/搜索不靠TTL周期性全量重建。

空授权源集合返回空目录，不能回退为全部合约；叶子响应的来源成员也裁剪到已解析源范围。来源选择/权限判断仍在现有 Manager 路由，缓存不授予权限；运行/下单仍须独立预检实时身份、数据、覆盖范围与执行计划，不能以这个 availability 快照决定允许执行。

## 多 Bundle、多节点边界

产品稳定 ref 与来源绑定不同。目标来源绑定必须明确 owning Manager/node、installation、Bundle身份/版本/内容指纹、member以及source_product_ref；同Bundle多安装、多节点不能被bare alias合并；同名异交易所/产品类型不能合并。series_variant遵循#120，与Product独立。

本批接口只解析本机运行时源；本机member归属出现歧义会报错。泛型索引的node/installation作用域隔离测试不是跨节点发现/同步验收。跨节点目录应读取现有授权投影，显示投影revision、离线/过期状态，不能在树展开过程中逐产品同步请求远端。当前contract-tree缺少完整跨节点binding合同，故仍是#451验收阻塞；不将节点alias或客户端本机位置冒充执行节点身份。

## 验证与限制

复现：`PYTHONPATH=. <GTHT-python> tests/benchmarks/product_tree_pages.py --objects 100000 --sources 20 --overlap 90 --samples 20`。

2026-11-03，arm64、Python3.14.0、SQLite3.53.2，隔离元数据桩，1k/10k/100k × 1/5/20源 × 0/50/90%重叠共27组，各20次热样本。100k组旧算法搜索p95约145–397ms，索引热搜索16–18ms、热页<=0.21ms；首次搜索620–898ms，最多43.42MiB临时文件；热请求新增源投影0。参考旧算法与新算法共享相同无I/O投影；其计时不含网络、真实provider延迟、完整树过滤/分类解析或浏览器。完整两算法进程峰值RSS<=155MiB，包含旧算法基线分配，不能作为索引单独RSS或生产资源上限。

聚焦测试覆盖稳定ref去重、同名异ref、重叠源保留、分页边界、来源搜索、未加载页、失效/成员替换/删除、scope隔离、并发单次物化、LRU/对象/磁盘容量、清理、空可见源以及刷新后再展开。隔离的真实本地目录元数据另验收2,846个合约、29页，全部稳定ref集合相等，来源成员/家族保留，随后搜索新增逐产品来源投影为0；这是测试快照，不是在线数据库验收。浏览器fixture以900px/390px视口覆盖展开/续页/详情/刷新后再展开且无pageerror。未运行生产压测、未做跨节点验收；真实服务时延和完整浏览器交互预算仍需继续。
