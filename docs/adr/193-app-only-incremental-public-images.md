# ADR-193：固定运行时上的应用增量镜像

状态：实施中（2026-11-03，refs #443）。沿用当前批次已有的 feat/main 集成及两端发布授权，不改变 Manager、个人客户端、执行节点和 Data I/O 的职责。

## 基线与问题

公网根分区可用 12,609 MiB。普通构建检查保留 10 GiB，再预留 5 GiB 构建空间，因此当前拒绝完整构建。三份应用镜像均为部署日志里的 verified 版本，不能为赶过容量检查提前删除回退镜像。

对实际镜像 823a4a67c 与前一 verified 镜像 1fca2651 的只读层盘点：两者均有 38 层，实际仅共享 5 层；单镜像约 2.63 GB，CLI 字节码层约 3.01 MB，其余大层包含 Python 依赖和原生包。该盘点不是构建峰值测量，也不是浏览器或运行任务的性能测试。

## 决策

仅在构建依赖、原生引用、系统工具、基础镜像和 entrypoint 均未变化时，允许向已验证的不可变运行时追加一个应用层。以其镜像 ID 固定基础，以 Git commit/tree 和逐文件 SHA-256 固定变更；源检查禁用 replace objects、hooks、fsmonitor 和外部 diff。

读取基础镜像实际的版本文件、所有将替换/删除文件以及原生扩展 SHA-256。任何不符都停止，不凭标签猜测内容。源码来自干净且 HEAD 精确匹配的候选 checkout。依赖、vendor/native、Dockerfile、entrypoint、依赖安装器或未知构建输入变化必须使用普通构建，不扩大增量白名单来绕过检查。

候选在临时容器中组装：网络 none、无挂载、cap-drop ALL、no-new-privileges、1 CPU、512 MiB 内存及相同 memswap 上限、64 PID，并检查宿主可用 RAM 至少 1 GiB（不计 swap）及实际资源控制支持。只写应用文件和薄 CLI 对应的确定性 hash-based 字节码。编译视源码为数据，不导入因子或原生扩展。核对字节码与同一源码编译的 code object，随后检查实际 CLI 帮助、全部变更字节和原生扩展。恢复原 entrypoint/CMD/用户后提交候选镜像。

应用单文件最多 8 MiB，传输源码总量最多 32 MiB，新增字节码总量最多 32 MiB；单个新增镜像层最多 128 MiB。工作所在文件系统和 Docker 存储所在文件系统均保持原有 10 GiB 余量，各最多新增 256 MiB，步骤间复查。复用全部基础层，不复制、安装或构建 wheel，不调用 pip/Cargo/Maturin。失败仅清理本轮临时容器及本轮未使用候选镜像，不 prune 历史版本、数据或增量缓存。

新镜像必须完整保留基础的层前缀，恰好新增一层，并保留原生、Python 依赖标签与应用入口。镜像中保留不可变来源清单；既有发布入口继续负责授权、分支包含关系、预构建镜像核验、数据库发布回退流程和线上验收。该工具组装镜像，不能自行激活服务或登记执行节点。

## 验收与限制

聚焦测试覆盖依赖/原生/构建输入变化拒绝、脏 checkout、路径与符号链接、删除、大小预算、只读规划不执行源码和授权先于写入。真实公网候选另须记录基础镜像 ID、共享/新增层数、实际新增字节、CLI 字节码数量、原生 SHA-256 与耗时；通过后才由现有发布流程激活。

本决策不证明所有旧历史正文已经迁移，也不替代报告、权限、跨 Manager、回测与原生客户端验收。运行时依赖变更仍使用既有受限构建及 wheel 增量缓存流程。
