# ADR 008: 测试结果生命周期与闲置淘汰边界

## 背景

IC 与分组测试运行在持续存活的 `FactorTester` 上。最新因子值、IC 序列和最近一次分组明细需要在请求结束后继续供前端查询，但中间计算对象或被新运行替换的结果若继续被 `tester.results` 引用，会按运行次数累积高频大表。

## 决策

`FactorTester.results` 是当前交互状态，不是历史运行归档：

- `CrossSectionIC` 等仅用于一次 IC 调度的 scratch factor 在输出被提取后立即丢弃其 `FactorRunResult` 与中间缓存。
- 相同 alias 的业务因子再次运行并替换前端可见实例时，旧因子的结果立即丢弃；只保留最新因子值、收益、IC 和可能存在的最近一次分组结果。
- 同一因子的分组测试继续覆盖 `group_result`，以支持最近一次结果的明细/排名查询，不保存历史分组运行。

测试器本身的删除必须由明确的生命周期事件触发：

- 用户删除提交、应用模板清空当前页提交、登出或会话过期时，可删除对应测试器。
- 模块折叠、标签页切换、筛选后暂时不渲染等 UI 状态不能推断用户已放弃提交。

## 后续可选优化

对于保持登录或长时间打开页面的场景，可增加基于 `page_uuid` 最近活动时间的两级淘汰：先释放可重算的大型分析结果并让前端标记“需重新计算”，再在明确废弃页面后删除测试器元数据。该策略涉及产品交互语义，不在本次内存泄漏修复中自动启用。

## 结果

- 重复 IC/分组计算的内存占用不再因 scratch 或被替换结果线性增长。
- 最新结果的图表和分组详情仍可查询。
- 是否自动淘汰闲置提交被明确留作独立产品决策，避免静默丢失用户工作状态。
