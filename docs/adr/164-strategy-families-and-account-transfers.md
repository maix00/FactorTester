# ADR-164 — 策略家族配置与账户资金划转

## 状态

已接受；由 Issue #443 分阶段实施。本文确立配置和执行合同，不表示所有实盘适配器都支持资金划转。

## 背景

当前回测配置把因子分组、Long-Short 和用户策略源码拆成不同页面与操作入口；公共因子策略又把参数定义放在专用表单中。新增一种策略需要同时修改策略逻辑、页面、字段校验和 RunSpec 编译器，容易造成前后端字段漂移。

Nautilus 的策略通过 ExecutionEngine 向一个或多个执行客户端发命令。Venue、Account、Strategy 与 Portfolio 是不同对象：Venue/执行客户端拥有具体账户状态，Strategy 可以路由到多个执行客户端，Portfolio 汇总账户与持仓视图。标准 Strategy API 没有跨账户资金划转命令；模拟 Venue 之间也不是自动共享现金。

## 决策

### 策略家族、策略与策略组

1. **策略家族（StrategyFamily）** 是可复用、版本化的配置契约，声明其可选的策略实现、因子角色和参数 schema。家族 schema 只使用受支持的类型与约束：因子引用、产品组引用、整数、数值、枚举及布尔值。网页根据 schema 生成表单，服务器用同一 schema 校验。
2. **策略（Strategy）** 是可执行的版本化实现，可以是 Nautilus 内建实现或用户策略库中的 Nautilus 源码版本。策略属于一个家族，并固定实现版本；用户策略的参数 schema 也由该版本声明。
3. **策略实例** 是用户在回测配置中从家族选择策略并填写参数后产生的配置对象。实例引用家族版本、策略实现版本、表单值和所有依赖对象的不可变版本。
4. **策略组** 保留为前端回测配置里的组织和选择边界；它不是 Venue 或 Account。组内可以放多个策略实例，实例可以路由到多个 Venue；Venue 仍按 Nautilus 语义拥有自己的模拟或实盘账户。相同 Venue 的实例共享对应执行客户端的账户和撮合状态。

配置页提供一个“添加策略”入口：选择策略家族/实现后，由该家族的 schema 生成字段。因子横截面分组家族至少声明“因子”“产品组”“分组数”“分组序数”；阈值家族声明因子及入场、退出和方向参数。禁止为每一种内置策略再造专属的策略按钮或独立配置页面。策略库把可复用的策略家族与策略实现分别呈现；公共、本人和下级用户策略的权限范围仍按现有对象版本基础设施执行。

RunSpec 固定家族 revision、策略实现 revision、schema revision、参数值，以及因子、产品组和市场数据等引用的完整版本图。执行时不得读取“最新”家族、策略或数据定义。兼容读取旧配置只服务于显式迁移，不创建第二个权威写入路径。

### 账户资金划转

Strategy 提供统一的 `transfer_funds(source_account_id, destination_account_id, amount, client_id)` 调用，发送 Nautilus ExecutionEngine 资金划转命令。调用指定来源、目标、金额和币种，不隐式选择账户，不自动共享资金，也不跨币种换汇。

- **Backtest 与 Sandbox/paper：** 执行引擎解析两个账户的执行客户端。模拟转账必须先验证账户存在、币种一致、来源账户可用现金足够、余额不会溢出，再在同一引擎命令处理期间扣减与入账，并通过账户状态事件留下来源、目标和转账引用。未完成校验时两个账户都不变。模拟撮合和账户状态仍分别属于各自 Venue/Account。
- **Live：** 命令只交给明确支持该转账的执行客户端。券商/交易所未提供能力时返回明确的 unsupported 错误；成功提交只表示请求已被接收，最终状态由券商账户更新确认。跨 Venue 或跨 Account 是否可操作由真实服务方 API 决定；不能由 Nautilus 在本地合成余额变更，也不能声称任意券商账户间转账具有原子性。

统一 Strategy API 在三种模式可调用，但能力由执行客户端公开。Backtest/Sandbox 仅对模拟账户执行本地成对记账；Live 默认拒绝，具体适配器可实现其真实支持的范围。资金划转是策略在运行时发出的明确动作，不是策略源码或 Instrument 的隐式属性；若回测计划会发出划转，RunSpec 冻结该策略实现与参数即可，账户目标也必须是冻结的账户/执行客户端引用。

## 性能与一致性

划转不进入 Bar 热路径，只在策略显式调用时处理。账户定位通过执行客户端的 AccountId 索引完成，不扫描历史订单、持仓或行情。模拟路径对两个账户做常数次校验和更新；不得为策略复制行情或账户全量数据。账户事件若无法完整提交，本次模拟运行必须失败关闭，不能继续生成看似有效的结果。

策略 schema 在列表读取时按版本引用返回，不实例化 FactorExpr、不运行用户源码，也不触发跨服务器同步 I/O。表单候选列表允许懒加载；提交时才验证冻结引用图。

## 验收

- 一个可复用 schema 同时驱动前端表单与服务端验证；非法字段、未知策略版本或缺失因子/产品组 revision 在提交时被拒绝。
- 策略组页面使用单一“添加策略”流；公共分组、阈值和用户策略实现通过同一实例模型与 RunSpec 冻结流程。
- 同一策略家族多个实例共享单次因子计算/排序结果；策略注册字段不会导致重复市场数据物化。
- Strategy 在 Rust 与 Python API 均可发出资金划转命令；Backtest 与 Sandbox 对不足余额、币种不一致、未知账户及正常成对划转有覆盖测试。
- Live 默认 unsupported；能识别能力的执行客户端可显式接收命令，且本地不提前更改账户余额。
- 基准报告覆盖运行时、账户数量、调用数、样本数、耗时统计和峰值 RSS；Bar/成交热路径无回归。
