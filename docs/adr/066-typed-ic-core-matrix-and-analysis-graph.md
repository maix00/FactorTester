# ADR-066：IC 核心测试矩阵与类型化附加分析图

- **状态**：已采纳
- **相关**：ADR-050、Issue #182

## 背景

IC 测试曾把因子、产品范围、前瞻收益期、Delay、统计方法、滚动窗口、
重采样、分期、分组组合和结果文件混在同一组扁平设置中。这种表示无法区分
“必须先计算的核心 IC”与“消费已有结果的附加分析”，也无法表达多个输入、
共享子结果或合法的下游依赖。客户端因而只能硬编码字段和兼容关系。

## 决策

IC 运行配置由三个正交对象组成：

1. **核心测试块**：显式声明产品范围、冻结因子、Horizon、入场 Delay、IC
   方法和收益定义。批量添加是有预览计数及上限的显式笛卡尔展开；展开后按
   内容地址去重，输入顺序不影响执行身份。
2. **附加分析图**：后端注册每种分析的输入类型、输出类型、目标基数、
   `map_each` / `combine`、参数和兼容轴。权威模型是无环图，界面只把它投影
   为可展开的树、Chip 和子行。
3. **输出请求**：表格、SVG、JSON、CSV 和保留策略只决定结果投影与持久化，
   不伪装成分析节点。

一个产品范围仍对应一个 Job；同一 Job 内复用因子值并执行因子 × Horizon ×
Delay × IC 方法矩阵。跨产品范围的组合必须成为显式派生 Job。RunSpec（界面
统一译为“运行配置”）冻结规范化后的核心单元、附加分析图和输出请求，不能
包含界面的聚合维度、展开状态、选择状态或排序。

通用设置注册表只提供领域 manifest 的挂载 seam，不理解 IC 图语义。Web、
Swift 嵌入页和 CLI 消费同一份后端 manifest；客户端可以提前过滤候选，但
服务端 planner 必须重新校验类型、基数、轴一致性、循环和执行能力。没有真实
executor 的分析或设置不得出现在能力 manifest 中。

## 迁移

- 旧的滚动 IC、分期、重采样、分组组合和持有期半衰期逐项迁移为注册分析；
- 旧扁平字段一次性编译为相同图，新的 writer 不再产生旧结构；
- `group_adjust`、`by_group`、`min_cross_section_count` 必须接入执行器或从
  manifest 删除，不能继续处于“可配置但不执行”状态；
- 数值迁移以代表性旧配置逐项一致为验收，不以页面看起来相似为准。

## 结果

新增分析只需注册一次，并由 planner、RunSpec、Overlay、Job 结果和报告输出
共同消费。核心矩阵可以单个或批量编辑，分析可以共享输入而不重复执行；界面
仍保持紧凑树形交互，但不会成为执行合同的权威来源。
