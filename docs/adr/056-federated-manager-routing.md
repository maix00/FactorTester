# ADR 056：通过对等 Manager 进行跨服务器任务路由

## 状态

已接受。

## 决策

1. 每台主机的 7998 都是对等 Manager 的控制面入口。跨主机请求只能走“本机 7998 → 对端 7998 → 对端本地服务端口”，不直接暴露或访问 8000、7999 或 issue 服务端口。
2. `main` 与 `feat` 是服务能力和代码分支标签，不构成主从关系。每台 Manager 可以登记另一台 Manager，也可以接收另一台 Manager 的转发。
3. 超级管理员在 Web 设置中明确勾选本机对外提供的服务端口；未勾选的 worktree 不进入远端路由表。固定部署服务（例如远端 8000 main）作为该 Manager 的内建能力登记。
4. 明确指定 `server_id`、端口、分支或 feature 时必须精确匹配；目标离线或不存在直接返回错误，不回退到其他节点。未指定目标时，候选节点先按 Manager 心跳测得的 RTT 排序，再按服务负载、活动任务数和队列深度排序。
5. 任务列表在任务记录中保留 `server_id`、Manager endpoint/host、服务端口、分支和 revision，前端显示稳定的服务器节点列；IP/host 只作为展示信息，不作为路由主键。
6. SQLite/业务数据库同步不在本 ADR 范围内。当前联邦只同步服务发现、心跳和任务请求/投影，不把 SQLite 当作 active-active 数据库。

## 结果

- 本机没有 8000 时，仍可通过对端 7998 路由到对端 8000 main。
- 远端节点离线时，显式目标和已登记的 fan-out 查询会得到明确的 503，而不会误把任务送到错误端口。
- 任务 SSE 也通过同一条 7998 链路转发，任务索引会写入服务器节点信息。
