# ADR-143：查看因子序列作为平行测试类型

## 状态

已接受。

## 背景

因子详情已有“查看因子序列”动作，执行端也已有 `factor_evaluation` RunSpec、Job
与结果生成物，但测试台没有独立入口。后端注册仍通过“单因子/单因子家族测试”
容器间接发现 IC、回测和因子评估，导致页面分类、执行类型和结果类型互相嵌套。

## 决策

`factor_evaluation` 是与 `ic_test`、`group_test` 平行的测试类型，用户名称为
“查看因子序列”。它直接拥有测试台入口、独立 tab、公共设置 tab、版本化页面辅助
文档、RunSpec、Job 与结果生成物。结果实现位于
`test-modules/factor-evaluation/results/`。

产品组、产品分类、数据源、时间、频率、价格类型和因子设置全部复用其他测试配置页
已有的注册、内容 adapter 与 CSS。因子详情入口预填冻结 `factor_ref`；调用方提供产品组
时同时预填产品组，不创建第二套表单。

顶层测试注册表直接注册平行测试类型，不再注册“单因子测试”“单因子家族测试”
页面或子注册表。历史 HTTP 包名不能成为公开测试类型、RunSpec kind、页面标题或 CLI
导航语义；后续迁移该包时只允许保持协议 adapter，不恢复旧领域名称。

## 后果

- 工作台、智能体表单和 Job 详情消费同一份类型化配置。
- 因子序列与回测结果具有平行的代码 locality，并复用通用 Job 结果 tab 壳。
- 新测试类型直接加入顶层注册表，不再创建测试集合页作为中间 Module。
