# ADR-021：费率规则、费用计算与费用流水分离

- **日期**：2026-06-21
- **状态**：已采纳
- **关联**：ADR-018、ADR-020

## 问题

`fee_history` 容易同时指代两类不同数据：随日期变化的市场费率规则，以及回测中已经
发生的费用流水。旧数组引擎还把费用计算表示为整期矩阵操作，无法表达部分成交、
逐笔最低收费、平今/平昨差异，也无法保证事件回放使用原成交时的规则。

## 决策

费用拆成三个职责：

1. `FeeScheduleProvider` 是可插拔 Adapter，按产品和交易时点提供当时有效的市场或
   账户费率规则。数据库、本地数据源和外部框架可以各自实现该 Interface。
2. `CommissionModel` 是可插拔 Implementation，结合订单、实际成交价、实际成交量、
   持仓批次和 Provider 返回的规则，生成 `FeeBreakdown`。部分成交分别计算费用。
3. `FeeJournal` 是 Ledger 的只追加读模型，只投影 Fill 中已经冻结的费用事实。它不
   查询规则，也不重新计算费用，因此不是插件点。

`Fill` 必须携带类型化 `FeeBreakdown`，账务处理只读取其合计。事件重放不得重新查询
可能已经变化的费率数据。开仓、平今、平昨和交易所特例由具体 CommissionModel 与
持仓批次协作决定，不进入通用 Broker 的条件分支。

## 后果

- 历史费率可以独立入库、更新和替换数据源，不改变账本结构。
- 同一成交事件在任何时间重放都会产生相同现金变化。
- 费用流水可以按 run、strategy、portfolio、order、fill 和 instrument 查询。
- 无费率研究必须显式使用 `ZeroCommissionModel`，而不是隐式跳过账务步骤。
