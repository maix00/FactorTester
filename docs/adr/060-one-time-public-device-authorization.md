# ADR 060：跨 Manager 来源的一次性授权

## 状态

已由 ADR-103 取代。本文只保留历史背景；一次性的内部授权页、grant API 和 redemption API 已不再实现。

## 背景

浏览器 `IndexedDB` 按来源隔离。在 `http://192.168.1.20:7998` 生成的密钥不能由 `https://203.0.113.10:7998` 打开的浏览器读取。只把公钥存进 PostgreSQL 不能解决来源边界；把私钥存到服务器则破坏设备密钥设计。

## 历史决策

内部认证的 Settings 页面曾创建绑定到目标 `server_id`、目标 Manager 端点、授权账户和具体语言快照的短期一次性授权 grant。PostgreSQL 只保存 token 的 SHA-256 哈希、所有者、目标、语言、过期时间和审计元数据；单节点开发可使用 JSON 存储。`system` 语言会在签发端解析成 `zh-Hans` 或 `en`，目标页面不得用浏览器语言覆盖快照。

目标公共 Manager 曾要求通过 HTTPS 接收 grant，在目标来源生成不可导出的 P-256 WebCrypto 密钥，提交公钥并原子消费 grant、注册设备和签发普通会话 cookie。普通合规页没有注册按钮，只尝试同一来源已有凭据。

设备密钥永久绑定创建授权的账户；兑换和后续挑战校验都自动为该账户签发会话，客户端提供的用户名不能作为认证输入。更换绑定必须撤销后重新授权。原生 Swift 客户端可以把同一挑战/签名负载与 P-256 私钥放在 Keychain/Secure Enclave，但不能依赖浏览器 IndexedDB。

内部 Manager 曾从联邦注册表投影在线 HTTPS 公共目标，并根据延迟、负载和稳定服务器身份排序；客户端不硬编码公共 IP。设备记录只保存粗粒度客户端类型/名称、注册来源 IP 和最近观察到的 IP，不保存原始 User-Agent、浏览器指纹、MAC、IMEI 或位置。

## 历史后果

该方案不要求域名或 DNS，复制的授权链接受目标绑定、过期和一次性消费限制；内部来源注册的设备不会被静默视为公共来源设备。语言偏好由 PostgreSQL 权威管理，Manager 保留五分钟本地投影；数据库故障允许缓存读取但拒绝偏好修改。当前生产协议以 ADR-103 及其后续决策为准。
