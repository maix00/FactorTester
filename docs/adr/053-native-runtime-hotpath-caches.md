# ADR-053：Native 回测热路径缓存

- **日期**：2026-08-11
- **状态**：已采纳（性能审计阶段）
- **相关**：ADR-051、ADR-052

## 背景

短窗口 native profiler 显示，结果正确但仍有三类重复工作：

- 订单调度反复从同一价格表推断 bar 频率，并为单个时间戳构造临时
  `Index`；
- 默认策略账本路由在每个时间戳重复建立相同的策略/产品决定；
- 缺失显式最小手数时，整数持仓判定在每根 bar 重复解析同一账本配置。

这些操作不包含新的市场信息，也不应影响交易语义。

## 决策

- `MarketDataStore` 按价格表身份缓存执行频率；只有策略未提供已解析频率
  时才使用该缓存，跨交易时段的产品索引仍保持原有逐产品定位。
- 无自定义 `order_routing` 的默认策略/产品路由按静态键缓存；带自定义路由
  或显式订单账本的路径继续使用原来的时间戳级决策。
- `TargetStore` 缓存静态路由下的账本状态和缺失最小手数解析结果；如果行情
  已提供显式 lot size，显式值始终优先。
- `OrderStore` 缓存一个已创建订单解析出的账本，`LedgerState` 缓存预回放固定的
  `LedgerConfig`；自定义路由和显式账本仍在首次解析时执行原有校验。
- 单调价格索引的 next-bar 定位使用标量 `searchsorted`，非单调索引保留
  原 `get_indexer(..., method="bfill")` 兼容路径。
- `TableRowLocator` 对单调价格表保留 NumPy 视图，并按产品缓存列位置；订单执行
  只读取一个价格单元，不再构造整行 `Series`。订单流水的时间、策略和产品文本
  采用 run-scoped identity cache，但记录字段和数量不删减。
- 同一策略信号批次内的订单共享已解析的执行排程上下文（撮合模型、价格基准、
  延迟、频率和价格表）；产品索引定位及原有逐品种排程缓存仍独立保留。
- 默认路由同时保留可检查的对象键缓存和带对象引用的 identity 快速缓存，避免
  `UniqueNameObject` 热路径重复计算名称哈希；对象引用用于防止 Python id 重用。
- 现金约束的顺序模拟按账本只复制一次持仓快照；同一账本的多个订单仍在这份
  快照上按减仓优先、增仓顺序依次模拟，完整现金/保证金语义不变。
- `FlowContext.payloads_for` 按策略和事件 payload kind 缓存内部不可变元组，
  对外仍返回新 list，因此既避免重复 unwrap/filter，也不改变调用方对返回容器的
  修改语义。
- `OrderFlowStore.record` 在原生 `Order` 上直接读取 fields，并只计算一次数量派生
  属性；轻量测试对象继续走原有 `get` fallback，完整审计字段仍全部保留。
- `apply_order_fill` 复用批次中已经解析的策略配置，并在现金记账成交中只解析一次
  contract multiplier，同时用于持仓记账和名义金额扣款；独立调用现金记账函数时仍
  保留原有的可选回退解析路径。
- 字段状态初始化按相同 fallback policy 批量查询多个历史字段，避免为每个字段重复
  构造产品身份 query frame；批量查询遇到缺失字段时仍逐字段、逐产品执行原有的
  严格回退和交易所默认值路径。FieldHistory 的变更事件预计算 instrument-code 到
  完整产品名的匹配表，使用只读 provider frame 和 `itertuples`，不改变前缀匹配或事件
  顺序语义。
- 非审计运行的 `FlowContext` 不再为每次读写调用空的契约审计函数；step/audit
  模式仍完整执行原检查。

## 验收

- 现有 native backtest、订单生命周期、账本路由和 timer 测试全部通过；
- 同一策略/产品的账本选择、订单时间和权益曲线不因缓存改变；
- 与优化前父提交 `5a878750` 在固定两品种 10 日场景逐点比较：equity curve、
  position curve、target trace 和完整 order-flow audit 的 SHA-256 均一致；
- 在同一合成 10 策略、10 产品场景中，500 日约从 3.9 秒降至 2.8 秒，
   1,000 日约从 8.0 秒降至 6.2 秒（仅计 native `run`，机器相关）；后续排程
  上下文和持仓快照去重后，重新测得 250/500/1,000/2,000 日约为
  `0.84/1.71/3.56/7.51` 秒（同一机器，含完整 flow registry，仅计 native `run`）；
- profiler 显示执行频率推断不再随订单次数重复发生，窗口增长保持线性；
- 2024-01-01 至 2024-01-12 的同配置 SgCCS 五分组 Job，在字段状态批处理前后各组
  Total Return、风险指标和订单/目标语义保持一致；初始化字段状态仍是约 2 秒级成本，
  单次 Job 的绝对耗时受行情缓存和机器负载影响，不把一次运行的波动宣称为固定收益；
- `tests/backtest/native/test_market_data.py` 70 项、相关市场数据与完整引擎回归 79 项
  通过，新增测试覆盖相同 fallback policy 的字段批处理和原字段顺序保持。
- 自定义路由、显式账本、非单调价格索引和 step/audit 路径保留旧语义。
