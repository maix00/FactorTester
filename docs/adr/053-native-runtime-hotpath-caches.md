# ADR-053：Native 回测热路径缓存

- **日期**：2026-08-11
- **状态**：已采纳（性能审计阶段）
- **相关**：ADR-051、ADR-052

## 背景

短窗口 native profiler 显示，结果正确但仍有三类重复工作：

- 订单调度反复从同一价格表推断 bar 频率，并为单个时间戳构造临时
  `Index`；
- 默认策略账本路由在每个时间戳重复建立相同的策略/产品决定；
- 缺失显式最小手数时，整数持仓判定在每根 bar 重复解析同一账本配置。

这些操作不包含新的市场信息，也不应影响交易语义。

## 决策

- `MarketDataStore` 按价格表身份缓存执行频率；只有策略未提供已解析频率
  时才使用该缓存，跨交易时段的产品索引仍保持原有逐产品定位。
- 无自定义 `order_routing` 的默认策略/产品路由按静态键缓存；带自定义路由
  或显式订单账本的路径继续使用原来的时间戳级决策。
- `TargetStore` 缓存静态路由下的账本状态和缺失最小手数解析结果；如果行情
  已提供显式 lot size，显式值始终优先。
- `OrderStore` 缓存一个已创建订单解析出的账本，`LedgerState` 缓存预回放固定的
  `LedgerConfig`；自定义路由和显式账本仍在首次解析时执行原有校验。
- 单调价格索引的 next-bar 定位使用标量 `searchsorted`，非单调索引保留
  原 `get_indexer(..., method="bfill")` 兼容路径。
- `TableRowLocator` 对单调价格表保留 NumPy 视图，并按产品缓存列位置；订单执行
  只读取一个价格单元，不再构造整行 `Series`。订单流水的时间、策略和产品文本
  采用 run-scoped identity cache，但记录字段和数量不删减。
- 非审计运行的 `FlowContext` 不再为每次读写调用空的契约审计函数；step/audit
  模式仍完整执行原检查。

## 验收

- 现有 native backtest、订单生命周期、账本路由和 timer 测试全部通过；
- 同一策略/产品的账本选择、订单时间和权益曲线不因缓存改变；
- 在同一合成 10 策略、10 产品场景中，500 日约从 3.9 秒降至 2.8 秒，
  1,000 日约从 8.0 秒降至 6.2 秒（仅计 native `run`，机器相关）；
- profiler 显示执行频率推断不再随订单次数重复发生，窗口增长保持线性；
- 自定义路由、显式账本、非单调价格索引和 step/audit 路径保留旧语义。
