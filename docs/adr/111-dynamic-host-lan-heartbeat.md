# ADR 111：内网节点心跳动态发布宿主机 LAN 地址

## 状态

已接受。

## 背景

Docker Manager 只能看到容器与 WireGuard 网络，无法可靠推断 macOS、Linux 或
Windows 宿主机当前可供局域网客户端访问的地址。过去本机部署把 LAN IP 写入静态
环境文件；DHCP 租约、Wi-Fi 或默认网卡变化后，在线 Manager 会继续使用旧地址发送
心跳，令公网目录把过期地址显示为在线目标。

## 决策

1. 内网 Docker 部署不再接受或注入固定 LAN IP、Manager 客户端端点或 Artifact
   客户端端点。
2. 宿主机运行一个无第三方依赖的地址代理。它按操作系统读取默认路由与活动硬件
   网卡，不固定 `en0` 等设备名，并排除回环、链路本地、容器桥接和 WireGuard
   等虚拟接口。
3. 地址代理每隔数秒把地址和观测时间原子写入 Manager 已只为该部署挂载的 state
   root。Manager 不执行宿主机探测，只读取该短期快照。
4. Manager 每次生成联邦心跳时重新读取快照，并从当前地址生成 7998/7997 客户端
   端点；同一 `server_id` 的新注册原子替换旧地址。
5. 快照缺失、格式错误或过期时，Manager 不回退到旧值或容器地址，并停止续租该
   节点注册。公网目录在现有心跳租约过期后不再显示该内网节点。
6. 公网服务器的稳定公网端点不属于本决策；它继续使用公网部署自己的显式端点。
7. 地址代理必须由宿主机原生服务管理器托管：macOS 使用用户级 `launchd`
   LaunchAgent，Linux 使用用户级 `systemd` service。Compose 生命周期入口只负责
   安装、启动或停止该服务，不以 `nohup` 或 PID 文件维持后台进程。Windows 启动器
   后续接入时必须把同一代理注册为原生后台服务。

## 后果

- 宿主机切换网络后不需要重启 Manager 或 WireGuard；地址代理更新后，下一次心跳
  即发布新地址。
- 地址代理异常时会暂时隐藏内网节点，而不会误导客户端连接旧地址。
- Compose 运维入口负责地址代理与本机服务器栈的共同启停；发布 shell 退出不会
  终止代理。其他操作系统的部署启动器必须运行同一个 Python 地址代理；探测与
  快照协议本身不依赖 shell。
