# ADR 090：Swift 客户端 Manager 引导、测速与机构内网优先

## 状态

已接受

## 背景

FTClient 不能假定本机存在可访问的 Docker Manager，也不能从客户端网卡或访问来源
推断服务器地址。另一方面，公网 IP 可能变化，且多个公网 Manager 的网络距离并不
等同于服务器登记时的延迟排序。登录用户还可能属于只由某个内网 Manager 管理的机构。

## 决策

1. 每个 Swift 发布构建只内置一个公网 HTTPS 引导地址（当前为
   `https://101.133.144.27:7998`）。它是构建常量，不是用户账号、设备白名单或最终
   Manager 地址；公网 IP 变化时，在下一次 Swift 构建前更新该常量。
2. 首次启动的自动模式通过引导地址的
   `GET /api/server/network-info` 获取在线公网候选和内网节点目录。请求只携带
   `X-FactorTester-Client: swift` 并要求安全传输；服务端只公开地址、端口、在线状态
   和机构范围，不公开账户、设备、任务或生成物信息。
3. Swift 从当前设备并发探测全部未截断的 HTTPS 公网候选，以实际往返时间选择最快者；
   探测结果和选中的公网节点在一次 App 进程内缓存。登录态或 WebView 重建不会重复
   公网并发探测。设置页的“发现并切换到最近公网 Manager”是显式的 force 操作，才会
   清空缓存并重新测量。
4. 登录后，Swift 使用 `/api/me` 返回的机构 ID 精确匹配
   `internal_server_targets.managed_organizations`，只探测在线且管理该机构的内网
   地址。当前机构的内网选择按进程缓存；若没有可达地址，使用已经选中的公网 Manager。
   登出后直接恢复选中的公网 Manager，不重新测量公网候选。
5. 自动选择写入 ManagerConfig；手动在设置中填写的单一协议、主机和端口设置为
   `manual`，自动流程不会覆盖它。用户主动点击自动选择按钮后才重新进入自动模式并
   保存新选择。
6. 公网 Manager 的网络信息接口保留浏览器/普通 API 的登录限制，只对安全传输下标记
   为 Swift 的只读发现请求提供预登录例外。内部 Manager 可在私网规则下提供同一投影。

## 后果

- 首次打开无需预装本机 Manager；公网引导 IP 可发现后续公网 IP，客户端不需要硬编码
  所有节点。
- 自动模式的网络探测成本是每次 App 启动一次，登录只增加当前机构内网候选的必要探测；
  设置按钮提供用户可控的重新选择。
- 如果引导公网节点离线，客户端按 ADR 091 进入手动配置页；不会把失败结果写成用户手动
  配置，也不会无限重试或把不可达内网地址当作可用地址。
- 机构范围由 Manager 注册信息提供。旧注册记录缺少该字段时，服务端按节点角色应用
  部署默认（内网 `GTHT`、公网 `default`），避免客户端猜测机构。
