# ADR-192：报告正文的 CouchDB 权威与旧存储退出

状态：实施中（2026-11-03，refs #443）。依据用户已确认的存储方向、两端发布授权，以及本轮明确的恢复、TradeResearch 命名和旧位置清理指令。

## 已测事实

- 两端分别通过真实 CLI 设备授权，issuer 不同、subject 不同；验证的稳定身份相同。两端授权目录的 ref 集合相同：10 项 Research、11 份 Report。
- 原生客户端拒绝 `research:migrated:` 已修复。两端各实际导入 10 项研究元数据，重复扫描没有重新排队；这不等于正文已经迁移。
- 内网报告存储未配置，公网对应的新式发布快照缺失。原来可见的目录及投影不能证明可编辑源已经进入 CouchDB。
- 用户从回收站恢复的 maxa/maxb 目录有 15 个分支 HEAD，公网工作区有另外 4 个。它们的报告身份合起来覆盖目录里的 11 份报告。旧引用类型、一个被拒绝的待更正提交和传输大小仍需逐项处理。
- 原研报可编辑包原为 23,770,960 bytes 的不压缩 ZIP；确定性 deflate 后为 2,910,222 bytes，原验证器检查通过，共 143 个节点、36 个文件对象。探测耗时 0.349 s，仅是本机序列化实验，不是浏览器端到端延迟。

## 决策

Report、Branch、可编辑树、选定附件和业务版本保存在 CouchDB。关系目录只保存引用和查询投影。文件系统用于有界缓存、离线待发内容和执行临时目录；共享报告的已确认版本从 CouchDB 恢复，不能依赖旧 Profile Git 工作区或 mirrors 才能读取。

沿用既有 Manager 用户授权、Keycloak 资源、受信 peer 网关及 7997 对象适配器。每个分支明确保留字节所属的 Manager；个人桌面客户端不登记为执行节点。不同 realm 的同名用户不能合并会话或权限。跨 Manager 读取仍核验源报告、实际存储服务器和受托主体。

CouchDB `_rev` 仅用于当前 HEAD 的 CAS。业务版本另存为不可变、内容寻址的记录，绑定原报告、分支、稳定 owner 和 Keycloak 资源。历史读取使用当前有效权限。附件按固定上限分块去重；ZIP 的对象边界允许相邻版本复用未变化的资源，并保留原始 ZIP 字节。数据库压缩或清理 MVCC revision 不应销毁业务版本。

确定性压缩不放宽限制：单次可编辑传输保持 8 MiB，解压总量保持 64 MiB，Manager 请求保持现有预算。版本字节块最多 4 MiB，读取验证大小和 SHA-256，限制解压输出。目录读取不加载整份树或附件，不运行因子代码。

旧 Graph 类型及已无法解析的历史引用必须保留原类型、目标和显示文字，以明确不可执行的历史引用表示；不能恢复 Graph 服务，也不能删除引用来通过校验。兼容转换生成后继版本并记录原 root/ref 映射。未完成提交保留其意图及诊断；没有证据时不能当作成功、丢弃或自动重放。

迁移专用的 v4 可编辑包在私有内容对象中携带原始 HEAD、可达原始节点、节点转换映射、恢复前异常字节及 Git blob 依据、被拒绝的提交记录。该对象最多 32 MiB，并计入已有的 64 MiB 解压总预算；普通报告仍可使用 v2/v3 包。读取时重新检查原节点内容地址并重现惰性的引用转换，不执行原始脚本或 Graph。缓存导入和后续导出保留该对象，不能仅把迁移证据留在即将清理的源目录中。完整 Job 表格数据缺失仍阻止对应分支迁移，不能使用图表或预览行替代。

实际存储切换显式启用 `storage_cutover`，即使正文节点没有改变，也创建迁移后继 generation，并保留原 HEAD/root。已有目录同一 generation 的投影哈希与迁移投影不同不能覆盖，不能放宽分支 CAS 或伪称字节相同。单纯兼容性预览默认不递增未变化的树。

个人客户端内容使用 `~/Documents/TradeResearch`，机构 Manager 的本机数据使用 `~/Documents/GTHT/TradeResearch`，应用状态统一到 `~/Library/Application Support/TradeResearch`。这些根分别承担个人客户端和机构服务职责，不因同在本机而合并主体或拓扑。路径转换针对已核对的存储配置，不重写不可变对象 ref。旧根目录下的行情、因子工作树、其他用户数据和执行产物须分类并完成对应转移，不能把整个目录当作报告缓存删除。

## 迁移和验收

1. 只读生成逐报告、分支、owner、源 HEAD/root、附件和待修复项映射。生成有界临时传输载荷，保留源文件直到验收完成。
2. 核对每个目标的当前版本与实际 Keycloak 权限；原子发布对应版本、正文和附件，不改变原报告身份，不产生全局删除。
3. 从 CouchDB 和全新缓存读回，对比对象 ref 集合、树根、正文、附件 SHA-256、分支及版本历史；覆盖权限撤销、冲突、离线重试和两端读取。
4. 切换配置和常规读写入口，核查实际运行路径，证明旧目录没有活跃写入者或独有数据。
5. 用户已明确授权清理被替换的旧存储位置，并明确不需要额外备份。该范围内不再复制整份旧目录；保留规范业务版本和迁移回执。仅在上述验收完成后删除已退出的旧位置，不扩大到源码 worktree 或仍需复用的增量构建缓存。

迁移过程中的失败必须保留明确状态，不以缺失文件推导 tombstone。未验证的分支不算完成。回退使用已确认的 CouchDB 业务版本及精确配置映射；不会重新启用旧内容权威或长期双写。

## 分支与阅读入口

目录中的 `p-<64 lowercase hex>` 是 CouchDB 发布的正式命名空间，与原 20–64 字符的发布引用分离；分支行以 `source_kind=couchdb` 明确其来源。登记时验证当前用户、已预留的精确 Profile 写者、当前报告 write/share 权限以及存储端的报告、分支、版本和 Manager 身份，不能使用请求自报的版本或路径。普通旧发布引用继续走原校验，不能回退读取另一来源。

React 的章节索引、章节正文、附件和 Markdown 读取使用已有 CouchDB 发布端点的显式阅读投影，浏览器位置仍是 `/app`。跨 Manager 读取扩展现有受签名 shared-report 操作的 `source_kind=catalog` 选项，保留目标 realm 委托主体、当前准入及报告权限检查；既有调用默认 local，不复制用户 token、不添加节点或另一同步通道。PDF 继续由原生客户端提供；服务端请求明确返回 501，不伪造 PDF。
