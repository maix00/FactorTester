# ADR-131：客户端本地目录与带时间范围的绑定快照

> **编号迁移说明：** 本文原文件名为 `048-client-local-catalog-and-binding-snapshots.md`。因 ADR-048 已用于
> 冻结因子身份，本文迁移为 ADR-131；决策内容不因重编号改变。

## 状态

目标决策已接受；本地目录与只读迁移预检已实现，服务端旧绑定在完成可验证迁移前不删除。

当前因子/产品公开 API 与 CLI 的统一入口另见 ADR-141。本 ADR 仍约束客户端本地目录的快照、绑定和事务
语义，不把 Manager 的远端目录响应冒充成本地权威。

## 背景

产品、产品组、因子和因子集合既可能来自服务器，也可能来自客户端本地数据源。把它们全部当成当前服务器工作区的配置，会把本地研究错误地绑定到某个活动工作区或某个因子家族，也无法表达一个产品组在不同时间范围内的成员变化。

旧产品组保存的是分类器选择路径和排除路径。分类路径不是具体产品身份，必须在带版本的产品目录快照中解析后才能形成可复现的成员集合。因子和因子集合还需要保存源码仓库、Git commit、blob 和成员 hash，才能让后续任务复用同一个冻结对象。

## 决策

1. FTClient 在自己的应用支持目录维护一个 SQLite 目录数据库。它是设备本地产品、产品组、因子、因子集合和绑定关系的权威来源；服务器同步只产生带 `sync_state` 的关系状态，不把服务器响应直接当成本地身份。
2. 产品身份拆成 `source_id`、Python 类路径和 alias。类路径只包含 `Product` 分类器的可见 Python 类；`Category` 选择路径和完整 `/_products/<alias>` 对象路径不能写入 `class_path` 字段。
3. 产品组拥有产品成员和因子/因子集合绑定。绑定记录保存 `valid_from`、`valid_to`、关系 revision、来源 revision 和状态；因子本身不反向保存产品组列表。
4. 因子 revision 和因子集合都必须绑定仓库、Git commit、Git blob、源 hash；集合成员按稳定顺序保存并计算 member hash。普通 factor 是单成员集合的语义别名，但数据库仍保留清晰的 `factor` 与 `factor_set` 类型。
5. 所有本地写入通过短事务完成，使用 SQLite WAL、外键和按 owner/group 的索引。查询只返回本地已登记的对象，不在列表命令中隐式访问服务器或重新解析完整目录。
6. 旧产品组迁移第一阶段只允许只读预检。若存在分类路径，必须绑定具体目录 revision 并生成成员 hash 后才可导入；预检不写本地数据库、不删除旧绑定。只有完成计数、成员 hash、时间范围和状态校验后，才允许另一个明确的迁移步骤执行删除。
7. `owner_ref` 表示对象所有权范围，不强制所有对象绑定某个 Profile。公共因子可以使用公共 owner；Profile 私有因子、集合和产品组使用稳定的 profile/user owner。研究 branch、workspace 和 Graph 不得作为目录对象的隐式 owner。

## 后果

- 本地和服务器可以共享对象字段与关系语义，同时保留各自的可用范围；本地数据源无需先注册到服务器才能登记。
- 目录加载从大量 JSON 文件变为索引查询，关系更新可以原子提交；SQLite 文件和 WAL 需要随客户端生命周期维护，不能在报告渲染期间删除或重建。
- 旧分类选择路径不能直接被当成 concrete product。迁移前会明确报告需要目录快照，避免静默改变研究产品范围。
- 服务器旧绑定暂时保留，直到迁移命令产出可审计的成员和版本对照；任何自动清理都必须是单独的、显式的破坏性操作。
