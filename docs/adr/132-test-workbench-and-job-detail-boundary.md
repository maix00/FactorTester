# ADR-132：测试工作台与 Job 详情边界

> **编号迁移说明：** 本文原文件名为 `050-test-workbench-and-job-detail-boundary.md`。
> 因 ADR-050 已用于 BAR 可见性契约，本文迁移为 ADR-132；决策内容不因重编号改变。

## 状态

已接受。

## 背景

旧服务端口的 IC/分组回测页面把测试配置、瞬时运行控制、任务监视、领域结果
和生成物管理合并在一起。当前客户端已有由 ResearchRun 和 JobAttempt 支撑的
跨端口持久 Job 页面；照搬旧页面会产生两份进度、冻结配置、结果和生成物真相。

## 决策

测试工作台拥有作者和比较功能：可复用设置/模板、因子/因子集/产品组/分类/
策略选择、每次运行字段、执行矩阵预览，以及每个独立冻结产品范围的提交。它
可以嵌入紧凑的结果预览，但不成为执行记录。

三个对象保持不同：

- 测试配置是生成运行的规范化应用设置；
- RunSpec 是由该配置生成的内容寻址执行契约；
- Job 是一次具体执行尝试及其保留输出。

运行配置页面把来源配置身份、冻结配置 payload 和剩余执行契约放在一个共享的
懒加载视图中。Web 和 macOS 通过 RunSpec 哈希复用同一个独立 tab；展示标签和
URI 写法不产生新 tab，Job 身份仍按执行目标区分。

Job 详情是执行记录的唯一来源，包含生命周期、进度、调用方、研究绑定、冻结
配置、全部结果/生成物，以及生成、下载、删除、审批、逐步、取消、重试和从
冻结运行恢复为可编辑配置等动作。

IC 在一个产品范围内建立一个 Job；因子 × 前瞻期 × 入场延迟 × IC 方法矩阵在
同一 Job 内复用因子值，矩阵单元不是 Job。多个产品范围因 RunSpec 和结果独立
而成为独立 Job。

IC 与回测结果查看器是共享模块。工作台和 Job 页面挂载同一声明、解析器和结果
状态模型，不复制图表/表格实现。旧交互按语义迁移；影响执行的字段必须在设置
注册表声明并冻结，未被执行器消费的占位字段不恢复。

## 后果

工作台保留研究交互，Job 详情仍是执行真相；跨入口打开配置或 RunSpec 使用
明确链接而不是把不透明 JSON 复制回工作台。恢复旧 Web 行为变成基于契约的
缺口审计，而不是源码搬运。
