# ADR 007: 异步产品面板的交易窗口语义

## 时间
2026-05-26

## 状态
已接受

## 背景

表达式引擎在同一张面板中对多个品种执行 `rolling()` 与 `shift()`。不同期货品种可能具有不同的日夜盘时段；将每个品种的原始时间序列合并到统一索引后，某些品种在其他品种开盘的时点上会出现对齐填充的 `NaN`。

现有时间窗口换算将 `Timedelta` 分解为整日部分与日内部分，并使用每个产品 `DataMeta.day_periods` 将整日部分折为整数 bars。该做法在密集或同会话面板中成立，但在异步面板中产生两个问题：

1. 对 `1d` 等整日窗口，各品种得到不同的整数 bars，无法表达同一个交易日跨度。
2. 对 `9m` 等日内窗口，普通按行 `rolling(int)` / `shift(int)` 会把其他品种引入的填充位置当作本品种的一根 bar，拉近实际历史窗口。

已有 `data_present_mask` 能表示原始数据中是否观察到一根 bar，并已用于分组测试识别异步品种；但它无法区分“产品此时本来不开盘”与“产品本来开盘但数据缺失”。这一区分对窗口计算是必要的。

本 ADR 修订 ADR-001 中“多品种窗口按产品 `day_periods` 解析”的宽泛结论：该做法只保留为密集/同会话快速路径，不是异步面板的正确性语义。

## 决策

### 1. 时间窗口保留结构语义

时间窗口不得先行压缩为一个通用整数。解析后保留两个部分：

```
WindowSpec(days, remainder)
```

- `days`：完整交易日跨度。
- `remainder`：小于一个交易日的盘中时间跨度。

例如 `1d + 9m` 的含义是“向历史回退一个交易日跨度，再按该产品计划交易的分钟 bars 回退 9 分钟”，而不是对每个产品计算 `day_periods + 9` 后用普通 DataFrame 行号滚动。

### 2. 面板时间线区分计划时段与观察数据

表达式求值上下文应能够取得面板时间线：

```
PanelTimeline(
    trading_days,
    scheduled_mask,  # T × P
    observed_mask,   # T × P
)
```

- `scheduled_mask[t, p]`：在交易规则/时段模板下，产品 `p` 在面板时点 `t` 是否计划存在一根 bar。
- `observed_mask[t, p]`：加载的原始数据是否确实提供了这根 bar。

两种典型空值：

| 场景 | `scheduled_mask` | `observed_mask` | 窗口行为 |
|------|------------------|-----------------|----------|
| 短夜盘产品在长夜盘额外时段的填充位 | `False` | `False` | 日内余量计数跳过 |
| 应交易时点发生数据断档 | `True` | `False` | 占据时间位置，计算结果保留缺失风险，不用更早值静默补足 |

`scheduled_mask` 必须来自可解释的产品交易时段接口。产品分类中的“日夜盘”描述可作为数据来源，但应先规范化为明确的时段模板接口，而非在算子内解析分类展示字符串。

### 3. 窗口起点以索引器表达

引入逻辑概念 `WindowIndexer`，按当前结果位置与产品生成窗口边界：

```
start_positions = WindowIndexer(WindowSpec, PanelTimeline).start_positions()
# shape: T × P
```

其行为为：

- **纯日内窗口**（如 `9m`）：沿每个产品的 `scheduled_mask` 计数计划 bars，跳过异步填充位置。
- **纯整日窗口**（如 `1d`）：沿交易日标签回退交易日边界，保持同一面板上的共同交易日跨度；不以各产品独立 `day_periods` 改写窗口含义。
- **混合窗口**（如 `1d + 9m`）：先定位整日跨度边界，再从该边界按产品 `scheduled_mask` 处理日内余量。

滚动聚合读取该边界范围内的已观察值；若计划窗口内的数据缺失，按具体聚合算子的 `min_periods`/缺失传播规则显式表现，而不是通过扩大窗口搜寻更早值来弥补。

### 4. `WindowBarsExpr` 只表达固定局部 bar 计数

`RollingExpr.bars` / `WindowBarsExpr` 的使用范围限定为：窗口在当前求值上下文中能安全解释为单一局部 bar 数的情形，例如同会话分钟数据上的 `W='9m'`。

- 对 `VoTideSpeed` 这类纯日内窗口动态截断，`window.bars - 1` 仍是清晰且有效的 DSL。
- 对异步面板上的整日或混合窗口，如果边界无法表示为单个标量 bars，`.bars` 必须明确拒绝求值，不能返回有误导性的整数。
- 未来若动态截断需要支持混合窗口，应暴露基于 `WindowIndexer` 的边界表达式，而不是放宽 `.bars` 的含义。

### 5. `DataMeta.day_periods` 的保留范围

`DataMeta.day_periods` 保留用于：

- 单产品计算；
- 经验证 `scheduled_mask` 在所有产品间一致的密集/同会话面板快速路径；
- 展示和诊断统计。

它不得作为异步面板中整日窗口的最终正确性依据。

### 6. 上下文与结果的职责边界

窗口算子在表达式求值期间即需要时间线信息。因此：

- `PanelTimeline` 应在表达式求值前构造，并通过求值上下文传入 `RollingOp` / `ShiftOp`。
- `FactorRunResult` 可保存所用 masks 供分组测试、诊断与可视化复用。
- 只在因子求值结束后填充结果对象中的 `data_present_mask`，不足以支持窗口算子的正确计算。

## 兼容与迁移

1. 不同时段产品但尚未启用 `PanelTimeline` 的异步窗口，应优先暴露不支持或诊断提示，而不是静默沿用不正确的按行滚动。
2. 密集/同会话面板保持现有整数窗口快速路径，以避免无必要的性能退化。
3. 既有 `data_present_mask` 可逐步迁移为 `observed_mask` 的对外兼容别名；不得将其直接当作 `scheduled_mask`。
4. 未合入的 `wip/async-window-ops` 可作为按计划有效位置压缩/散回的性能原型参考，但需先接入本 ADR 的两类 mask 与混合窗口定义。

## 必须覆盖的验证场景

- 同会话产品：新路径与现有 pandas 整数 rolling/shift 结果一致。
- 不同时段、纯日内窗口：短时段产品跳过长时段产品引入的填充位置。
- 不同时段、纯整日窗口：所有产品沿统一交易日跨度定位边界，不因 `day_periods` 不同改变语义。
- 不同时段、混合窗口：整日边界共同、日内余量按产品计划 bars 推进。
- 计划时段内数据断档：缺失位置不被当作休市位置跳过，不静默拉入更早观测。
- 产品组加入不同时段品种后：已有品种在其自身计划时点的日内窗口结果不因 union 索引扩张而变化。
- 动态截断：纯日内 `.bars` 保持有效；不安全的异步整日/混合 `.bars` 明确失败。

## 实施切片

1. [#75](https://github.com/maix00/FactorTester/issues/75)：建立 `PanelTimeline` 与计划/观察双 mask，并提供同会话快路径识别。
2. [#76](https://github.com/maix00/FactorTester/issues/76)：将 `ShiftOp` 接入窗口索引语义，覆盖收益率与滞后表达式的异步面板行为。
3. [#77](https://github.com/maix00/FactorTester/issues/77)：将滚动聚合与位置算子接入窗口索引语义，并覆盖动态截断能力边界。

## 后果

### 正面

- 因子结果不再随产品组中额外长夜盘品种的加入而无意变化。
- 数据断档与休市填充被显式区分，研究结果更可审计。
- 日窗口与日内窗口的含义保持业务直觉，而非受 union 行数偶然影响。

### 代价

- 求值上下文和窗口算子需携带更丰富的时间线信息。
- 异步窗口不能完全依靠 pandas 原生固定长度 rolling 的快速实现。
- 交易时段模板必须成为明确的数据契约。

## 被取代的约定

- ADR-001 中关于多品种 `Timedelta` / `DataFreq` 窗口一律按各品种 `day_periods` 解析的表述，在异步产品面板场景下由本 ADR 取代。
