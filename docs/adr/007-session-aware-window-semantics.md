# ADR 007: 异步产品面板的交易窗口语义

## 时间
2026-05-27

## 状态
已修订

## 背景

多个品种的分钟数据合并到统一索引后，交易时间段较短的品种会在其他品种的额外时点产生对齐空行。若直接在 union 索引上执行 `rolling(int)` 或 `shift(int)`，这些填充位会错误地占用本品种的历史窗口。

曾拟引入 `scheduled_mask` 区分计划交易与实际观测。但当前系统没有可靠、统一的计划时段来源；用品种描述或观察数据反推计划时段，反而会改变现有数据语义。因此窗口计算仍以 `master` 已有的原始数据存在性为准。

## 决策

### 1. 默认交易位置由原始观测定义

`PanelTimeline` 只携带初始原始数据形成的 `observed_mask`，它与计算结果中的 `data_present_mask` 含义一致：某个产品在某个原始索引位置确实存在 bar。

- 默认不存在 `scheduled_mask`。
- 没有观测到的时点，无论原因是休市还是缺失，在异步窗口中均不占用该产品的 bar 位置。
- 将来只有在存在权威交易日历数据源时，才另行设计计划时段与缺失诊断。

### 2. 同交易位置保持 master 行为

若产品组在原始数据频率一致的条件下具有相同 `observed_mask`，则认定具有相同交易时间位置。此时窗口先按既有规则换算 bars，之后完全沿用 `master` 的 DataFrame `shift` / `rolling` 行为。

### 3. 异步交易位置采用矩阵压紧计算

若产品组的 `observed_mask` 不同：

1. 按每列 `observed_mask=True` 的位置，将各产品原始值压紧到稠密矩阵；
2. 时间窗口仍按各产品的 `DataMeta.day_periods` 与日内余量解析为 bar 数；
3. bar 数相同的列作为一组，以 pandas/NumPy 矩阵运算执行 `shift` 或 `rolling`；
4. 将结果仅散回原始 `observed_mask=True` 的位置，填充位保持 `NaN`。

因此整日倍数与日内余量均包含在每个产品解析出的窗口 bars 中；不同交易时段产生的 union 填充行不参与余量或整日窗口计数。实现不得按时点或窗口单元逐项循环。

### 4. `WindowBarsExpr` 的范围

`.bars` 只有在窗口可在当前产品集合解析为一个共同标量 bars 时才成立。产品的整日窗口 bar 数不同时，继续明确拒绝 `.bars` 求值，避免把不一致的边界伪装成单一整数。

### 5. 动态截断边界

动态截断滚动窗口目前仅保留同交易位置的既有路径。异步交易位置下，截断边界需要一套与压紧矩阵一致的新表达，未实现前应明确报错而不是静默按 union 行计算。

## 验证场景

- 同交易位置产品：结果与 `master` 固定 bars 的 pandas 路径一致。
- 不同交易位置、日内窗口：跳过初始 `observed_mask=False` 的填充位置。
- 不同交易位置、整日或混合窗口：按各产品解析 bars，在压紧矩阵上分组计算。
- 产品组加入交易时间更长的品种后：原品种自身已观测位置的窗口结果不受 union 扩展影响。
- 异步整日 `.bars` 与异步动态截断：不支持的标量/边界语义明确失败。

## 后果

- 不再引入没有权威来源的交易时段推断，与 `master` 的原始数据判断一致。
- 异步窗口避免对齐填充造成的水平直线或窗口缩短问题，并保持矩阵化计算。
- 默认模型无法区分真实缺失 bar 与非交易位置；这是在没有计划时段数据契约时的显式限制。
