# ADR-110：嵌套策略编辑器与作用域作者流程

## 状态

已接受。

## 背景

回测策略组、分组多空和派生策略都需要覆盖测试配置上方的统一字段。此前策略组的覆盖编辑器只出现在列表行内，新增/编辑表单中的因子和产品组候选范围也没有明确绑定外层字段，容易把外层范围和用户可见目录混在一起。

## 决策

1. 后端 settings manifest 注册 `strategy_editor` 契约。契约声明三个默认内层 tab：分组、因子执行、产品组；同时声明外层因子/产品组选定字段、只能由外层挂载的字段，以及派生策略的覆盖语义。
2. 前端策略编辑器使用共享 `FTTabChipContent`。内层默认 tab 始终挂载；其他可覆盖 tab 由用户在同一个内层管理入口手动挂载。
3. 外层因子或产品组 tab 已挂载时，内层只能使用外层已选值；外层已挂载但没有选值时，禁止保存和现场新建，并提示用户设置或取消挂载。外层未挂载时，回退到当前 Manager 已加载的可见目录。
4. 派生策略仍是普通策略，创建时继承父策略字段，之后可以修改对应字段并以覆盖值保存；任务、模板、运行时间等 authoring-only/外层字段不进入内层覆盖。
5. 因子现场新建复用因子家族选择、源码校验、参数解析和 LaTeX/详情链路；产品组现场新建复用产品组独立编辑器，并接收当前测试中刚创建的临时产品分类。
6. 分组多空仍以已有分组为长/空腿，但使用同一嵌套 tab/覆盖模型；自定义策略保留原有源码 tab，并由同一嵌套编辑器承载范围摘要与手动覆盖。覆盖值在实际设置后随运行输入提交。
7. IC 测试复用同一份后端策略编辑契约与因子/产品现场新建 overlay，但不虚构回测策略组列表；IC 自己的因子和产品候选仍由其现有配置 surface 管理。

## 后果

- 候选范围的权限边界由 manifest 与统一解析器共同决定，不由某个页面临时拼接。
- 首次打开策略编辑器可以先渲染结构；因子/产品目录按需加载，冷 workspace 不会把空目录误认为没有候选。
- 现场创建得到的对象会回填当前测试状态，保存时随配置冻结；仍需由现有服务器对象接口完成持久化。
- 旧的行内覆盖内容仍保留用于列表快速编辑，避免破坏已有任务配置；新的表单使用同一覆盖模型和 tab 组件。
