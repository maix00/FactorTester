# 153 — 因子集合登记生命周期与成员事件

状态：采用；关联 #390。

集合的逻辑身份为登记用户、集合 owner_ref 与 set_id；成员版本继续使用现有内容寻址 ref。改变成员生成新 ref，不修改历史版本的 identity。退出当前登记仅令 registration_active=false，保留旧的冻结成员，常规目录不把它当成可运行的新登记。

逻辑集合用 `factor_set_head` 保存当前版本指针，复用 account-domain 冲突检查；不同成员 ref 不再各自竞争成为当前版本。

成员事件使用 account-domain 的 factor_set_event，逐成员记录 added/removed、逻辑集合身份、操作编号、时间、原因与完整冻结成员，复用 outbox/cursor/conflict。每条事件有独立 UUID，反复移除/加入同一成员不会相互覆盖。当前登记、旧版本退役与事件在同一 SQLite 事务提交。既有集合只从首次可观测状态建立基线，不推测之前的操作时间。

历史列表分页且按集合可见权限授权。点击成员进入已有因子详情；持久 URL 携带集合引用和登记用户，服务端验证该因子确为该集合历史成员。家族源码使用现有不可变公式指纹与 ADR-146 的源码版本提供方，不依赖当前家族仍存在，不将源码嵌入同步元数据。不能靠客户端提交的 frozen JSON 扩大访问权限。

删除/归属转换仅更新当前登记及当前集合成员；历史集合、事件与测试提交快照保留。空集合退出登记但仍能从已打开的历史页面读取事件。当前目录不通过历史版本重新生成已删除的因子或家族。

目录投影统一由 `factor_family` 当前 head 决定家族是否有效；`factor_source` 仅表示源码提供方，允许因历史读取而继续存在。公共与本人目录共用当前 head 优先规则：存在 head（包括 tombstone）时，任何服务器的 provider 元数据均不得补回或覆盖该家族；仅无 head 的旧记录允许兼容投影。读取目录不通过删除历史 provider 来纠正归属。
