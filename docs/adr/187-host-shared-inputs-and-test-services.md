# ADR-187：同主机共享数据与按测试类型选择执行服务

状态：需求与路线确定；仅共享身份/挂载前置项实施。跟踪 #448。

## 用户决定

一份配置只选择一个测试类型，例如回测、模拟交易、IC、因子序列。先显示可用服务声明
类型的并集，选择类型后再选择支持该类型的服务器/业务端口。不是一份配置选择多个类型。
Manager与测试执行分离；同主机的多个进程/容器复用不可变数据，前端按需读取。

## 现状与证据

66ee9a801 / Nautilus fd9b4e1ea4已验证T/TL各8根Bar的Catalog、冷共享和热共享回放，
使用真实原生因子策略，结果一致。但Decimal128对齐和存储列类型转换仍可能产生每运行
临时缓冲。默认仍为Catalog，并未证明全平台单副本或生产容量。

现有Manager路由、服务端口/联邦注册、Celery/RabbitMQ调度和Job目标信息必须复用。
当前Compose中Manager仍会在同一容器启动固定业务子进程；独立worker容器已经存在，
不能把本ADR写成已经完成控制/执行容器拆分。

原缓存键包括可见路径，默认身份使用hostname。容器挂载同一文件到不同路径、使用不同
hostname时会错过共享。第一批改为scope内设备号/inode/大小/mtime/ctime标识源文件，
保留路径用于本次读取变化检查；缓存v4。相同内容但不同inode仍不自动去重。

## 数据共享 Module 的 Interface 与 Implementation

公共数据Module以不可变Arrow块、来源身份、修订、类型和只读借用为Interface；源格式
解码、规范化产物和缓存回收集中为Implementation。平台、Nautilus和因子引擎分别通过
Adapter消费，不把Nautilus对象或目录结构变成平台Product模型。现有共享缓存是Seam，
不创建第二个缓存权威或调度器。

转换产物必须按输入身份、完整目标schema/精度/时间语义、转换实现版本去重并单次生产，
之后共享转换后的缓冲。不是给每个进程各自保留一份转换缓存。价格精度、可用时间和
元数据不得因去重被省略。此产物生产/接线尚未实现；当前仍是按批次转换。

因子同一Plan的CSE和多策略共享Actor应沿用现有alpha机制。跨运行只复用不可变结果块，
身份至少含节点/参数、冻结输入、产品集合及顺序、时间网格、日历/窗口/可用时间语义、
warmup与kernel版本。仅节点名称或表达式相同不充分；独立推进的增量状态不可共用。
当前alpha/warmup写范围有活跃修改，本批不修改这些文件。

## 同主机与生命周期

共享要求同一内核和底层文件、同一可信scope、共同缓存目录/配额以及兼容UID和权限。
Compose统一使用同一个STATE_ROOT下的shared-columnar，固定服务端设备身份为同一
Manager server_id，不以容器hostname划分。各服务须使用同一套资源配置；不要为worker
另造Manager身份。客户端用户来源仍使用独立client/owner/device作用域，不自动上传。
不将目录改为全局可写。Docker Desktop虚拟机与宿主原生进程不能据此共享物理页。

活动读者持强借用，释放后才可回收相关资源；排队任务只提供有界的弱预热提示，不提前
装入/固定全部输入；网页只借用本次显示所需块。没有活跃借用的派生产物按容量/LRU回收。
重试、取消、失败、worker被杀和队列重排必须释放/重建租约，不另建Job权威记录。
原缓存的文件大小配额不是RSS硬上限；多个4GiB worker不能因此被认为适合8GiB主机。
宿主总容量准入应复用既有dispatch能力，计入Manager/数据库/OS余量；尚未完成。
缓存是可删除派生物，不走账户对象同步，也不随发布复制到其他服务器。正式部署前需
确认备份排除该目录；本批没有执行或修改运行中的备份。

## 控制、执行与前端

Manager负责认证、目录/元数据、路由和状态展示，不承担回测计算。业务API与其worker
可独立容器/版本，使用现有队列和结果基础设施。真实物理内存共享仍只限同主机内核。
不同服务器必须传输/落地授权数据，不伪装成跨主机共享内存。

服务声明其实际就绪的测试类型、配置schema/版本和目标身份。Manager投影这些声明，
不靠安装了Nautilus就推断模拟盘/实盘可用。选择目标后，schema、预览、运行、Job和
结果路由保持同一server_id/port/部署版本；不可用时明确错误，不静默换端口。
服务切换应保留草稿、失效旧预览并拒绝乱序响应；前端类型/服务标签需多语言和移动适配。
能力投影复用现有服务注册，不新增账户对象同步协议。

建议先在同一Git仓库严格分离源码依赖、构建产物和运行容器，不把拆仓作为资源隔离
或内存共享前提。Manager不能直接导入执行引擎；测试服务通过版本化能力/schema和
既有Job协议接入。待协议和独立发布需求稳定后再决定是否拆执行仓库。当前没有获准
创建/迁移独立Git仓库，也没有进行此类操作。

行情初次只请求小范围、有界数量的粗粒度数据。更多历史/更细粒度由用户明确操作触发，
不能先读取全历史再在响应或UI截断。聚合/更多数据的范围、数量和加载状态需清楚表达。
当前图表设置与自动范围加载尚未完成此切换。

## 路线与验收

1. 同inode别名/不同文件、scope隔离和Compose共同挂载/身份的聚焦测试；不称为Docker实测。
2. 规范化产物单次生产、跨进程借用/回收、精度/元数据一致和内存基线。
3. 现有服务声明→Manager→单类型前端目标→冻结目标→Celery执行全链路。
4. 队列/前端生命周期、总容量准入、取消/崩溃/重试，以及按需图表读取。
5. 代表性本机多进程/容器和实际策略验收后，再申请部署；本ADR不授权部署。
