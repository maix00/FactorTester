启动模式

start_server.py 在 run_flask_server() 中根据环境变量自动选择模式：

开发模式

# 设置环境变量
export FLASK_DEBUG=1

# 启动
python start_server.py --port 8000
  • 使用 Flask 内置服务器（app.run(debug=True, use_reloader=True)）
  • 自动启用 Flask 热重载（检测 .py 文件变化自动重启）
  • DEBUG 级别日志

生产模式（默认）

# 不设置 FLASK_DEBUG，或 FLASK_DEBUG=0
export FLASK_DEBUG=0
python start_server.py --port 8000
  • 使用 waitress WSGI 服务器（生产级，8 线程）
  • 启动 自定义热插拔监控线程（每 3 秒扫描模块变化）
  • 自动打开浏览器

热插拔机制 (Hot Reload)

生产模式下，start_server.py 实现了自定义的模块级热重载：

  • 监控范围：Factors.、tools.、server.、sources.、Settings
  • 跳过模块：start_server（自己）、UniqueObject、IdleResourceManager（有复杂全局状态）
  • Reload 顺序：按 import 深度从小到大 reload（被依赖的底层模块先 reload）
  • 检测方式：对比 os.path.getmtime()

相比 Flask 原生热重载，自定义方案的优势是 不需要重启整个进程，只 reload 变化的 Python 模块。

⚠ 注意：热插拔只 reload Python 模块。如果修改了 HTML 模板或静态文件（CSS/JS），由于 Jinja2 模板缓存和浏览器缓存，需要手动刷新页面才能看到变化。

变量默认值说明
FLASK_DEBUG0设为 1 启用 Flask 开发模式（内置服务器+热重载）

GTHT_DATA_DIR../data数据文件根目录（Parquet 文件所在位置）

内存管理 — IdleResourceManager

tools/base/IdleResourceManager.py 是一个全局单例的 空闲资源回收管理器：

  • 命名空间：区分不同类型资源（datameta、roller_info 等）
  • TTL：每个命名空间独立的空闲超时时间（DataMeta 默认 5 分钟）
  • 触摸 (touch)：每次访问资源时更新 last_access 时间戳
  • 后台线程：每 5 秒扫描一次，释放超时未被触摸的资源
# 在 start_server.py 中启动
IdleResourceManager.get_instance().start(idle_timeout=10, scan_interval=5)

这样设计的原因是 DataFrame 占用内存大（特别是分钟级数据），在用户不活跃时自动释放，避免内存持续增长。

服务器管理

关闭服务器

管理员可以通过 POST /shutdown 关闭服务器（调用 os._exit(0) 强制退出进程）。

线程模型

  • waitress：8 个工作线程处理 HTTP 请求
  • 热插拔监控：1 个守护线程定时扫描文件变化
  • IdleResourceManager：1 个守护线程定时回收资源

所有守护线程使用 daemon=True，进程退出时自动终止。
