## 先确认任务状态 {#job-state}

任务状态描述执行生命周期，不直接代表研究结论。先查看任务详情中的状态、最近一次状态变化和当前 Attempt，再判断是否已有可读结果。

| 状态类别 | 含义 | 下一步 |
| --- | --- | --- |
| 准备或排队 | 任务已接收，正在等待执行条件或工作端口 | 检查执行计划、节点能力和队列状态 |
| 运行中 | 某个 Attempt 正在处理冻结输入 | 记录任务标识，之后可重新打开页面查询 |
| 成功 | 执行器报告完成 | 检查声明的生成物是否齐全且可读 |
| 失败或取消 | 本次 Attempt 未完成 | 保留 RunSpec 和日志，按[任务失败排查](/docs/job-failures)判断原因 |

任务详情来自 Manager 对 Job 和 Attempt 的记录。浏览器是否仍打开、页面是否仍在当前标签，不决定后台任务状态。

## 按顺序阅读结果 {#results-and-artifacts}

1. **看运行配置。** 打开冻结 RunSpec，确认因子和产品引用、时间范围、数据源、时区，以及实际生效的费率、保证金、价格基准和其他解析字段。
2. **看执行记录。** 检查 Attempt 的起止时间、状态变化和错误摘要。重试产生新的执行历史；不要用当前编辑器草稿代替历史输入。
3. **看结果摘要。** 从任务注册的结果表、指标卡和图表开始阅读，确认统计口径、样本范围和单位。
4. **看生成物。** 根据需要打开表格页窗口、图表时间区间或原始 Artifact。页面可以按需加载摘要、可视范围和细节；懒加载不改变完整 Artifact 的来源和内容。
5. **追溯研究证据。** 记录 Job、Attempt、RunSpec hash、输入引用和 Artifact。需要在 Research 或 Report 中引用时，再创建正式 Evidence 绑定，不要只复制一段数字或截图。

已注册的图表和表格视图应依据 Artifact 类型与 schema 选择。JSON 等原始文件用于下载和核对，不应取代已经注册的可读结果视图；文件扩展名本身不能说明业务含义。

## 结果异常的核对顺序 {#result-checklist}

如果结果表、图表和原始文件不一致，先比较它们使用的 Job、Attempt、Artifact 引用和时间范围，再查看展示请求的页窗口、降采样参数及时间口径。若原始 Artifact 可读而某个图表失败，应按展示问题处理，不要重新运行主任务。

如果任务没有结果，按“配置 → 数据 → 执行 → 生成物登记 → 展示”检查。只有确认冻结输入或执行本身有问题，才提交新的运行；新运行应保留新旧 Job 之间的关联，不能修改旧 RunSpec。
