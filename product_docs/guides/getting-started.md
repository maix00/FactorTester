## 平台由什么组成 {#platform-parts}

FactorTester 把产品库、数据源、因子库、测试配置、Job、生成物和研究对象分开管理。这样做的目的不是增加入口，而是让一次测试可以明确回答：使用了什么输入、采用了什么配置、在哪个执行端运行、产生了哪些输出。

平台有三类使用面：产品库和因子库提供可引用对象；测试工作台把对象编译成 RunSpec 并提交 Job；研究模块把 Job、Artifact 和外部材料组织为 Research、Report 与 Evidence。

## 第一次使用 {#first-use}

1. 在“产品库”确认产品、数据源、字段能力、交易时段和历史覆盖。
2. 在“因子库”选择可引用的具体因子或因子集合；需要临时定义时，先确认源码、参数和所有者。
3. 从“测试”选择 IC 测试或回测，先检查核心字段、条件字段和默认值，再提交。
4. 在“测试任务”查看进度、冻结运行配置、Attempt、结果目录和生成物。失败任务也要先看冻结配置和错误层级。
5. 需要形成可审计结论时，从“研究”创建或打开 Research，再将报告和证据正式绑定。

测试的字段类型、默认值和实际生效值见[代码架构与合规控制](/docs/compliance-architecture#field-contract)。

下一步可阅读[运行 IC 测试与回测](/docs/run-tests)。

## Web 与 macOS 客户端的区别 {#client-differences}

服务器只声明服务器能够提供的资源。Web 主要读取 Manager 提供的服务端对象；macOS 客户端还可以展示当前用户机器上的因子工作区、本地研究和本地数据源。客户端本地能力不会被伪装成服务器能力，服务器 Profile 的工作区副本也不能自动取得用户工作区的写权限。

## 首次提交前的核对 {#before-first-submit}

提交前至少核对研究对象 ref、产品范围、数据源和字段能力、日期和时区、测试类型、默认值来源、输出保留范围以及提交身份。显示名称适合人读，稳定 ref 和 hash 才适合复现与审计。
