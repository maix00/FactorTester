## 选择研究入口 {#choose-research-entry}

Research 是一项研究工作的协作上下文；Report 是其中可发布阅读的结构化报告。进入研究前确认当前连接的是哪台 Manager、当前使用哪个 Profile，以及目标对象位于本机还是服务器。不同位置的记录不会因为显示名称相同而自动合并。

电脑客户端可以新建本机研究，也可以在 Manager 新建研究；网页和移动端在 Manager 新建。研究列表按所有者、研究身份和位置展示对象。列表可见不代表拥有编辑权限，打开对象时仍由目标存储端校验访问权。

## 管理研究与同步状态 {#research-location-sync}

电脑客户端登录后会分批发现当前账号有权访问的服务器研究，并将新增或变化的研究排队导入本机。网络失败时保留待重试记录；旧 Manager 若不支持发现接口，客户端应明确提示能力缺口。

本机报告必须由用户明确发布后才进入服务器同步链路；已有发布记录会分批检查更新。服务器新建报告的首次导入和完整双向同步仍在建设中，因此本机与服务器列表不能被当成已经完全一致。同步状态应分别报告“本地已保存”“待同步”“已发布”和“目标端可读取”，不能用单一的“已同步”掩盖失败阶段。

## 撰写报告与绑定证据 {#author-report}

报告草稿由结构化组件组成。新增、移动或删除章节时，使用稳定 component ID 指定父容器和相对位置；不要用可能重复或会改名的标题定位。提交后保存操作收据和新 revision。未指定位置时，内容按报告领域规则写入末尾章节。

Job、Attempt、RunSpec、Artifact、权威外部来源和人工记录可以成为 Evidence 的来源。只有完成正式绑定的对象才是报告引用的证据；正文中提到对象名称或复制其结果文本，不会自动建立绑定。

发布版本是供读者读取的投影。继续编辑时从新草稿或分支开始，不应直接改写读者已看到的版本。章节插入、发布和阅读步骤见本章流程图；存储及并发边界见[研究报告实现](/docs/research-reports)。

## 发布前检查 {#publication-checklist}

1. 检查标题、研究范围和版本说明是否准确。
2. 打开每条对象链接，确认其引用稳定且读者有权查看。
3. 检查 Evidence 绑定、摘要展示和文件下载权限是否符合预期。
4. 确认本机报告是否需要显式发布，并核对目标 Manager 的支持能力。
5. 发布后从读者视角重新打开报告；如需撤销共享，核实服务端授权和客户端缓存失效策略。

报告可见范围、Research 的共享范围和生成物下载权是不同权限。公开报告不自动开放底层文件。
