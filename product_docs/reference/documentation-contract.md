## 文档的目的与读者 {#purpose-audience}

技术文档服务面向所有用户，解决“平台能做什么、对象如何关联、接口如何调用、实现在哪里”的问题。公开文档不是服务器源码浏览器，也不是某个部署的临时日志；敏感配置、令牌、用户私有文件和未发布实现不应进入这里。

内容按 Diátaxis 的四种需求分层：使用平台的教程、完成任务的操作指南、可精确查询的参考、解释边界和取舍的原理说明。实现细节放入实现架构区，避免在操作指南中堆积内部文件名。

## 登记规则 {#registration}

每个公开页面都必须在 manifest 中登记唯一 slug、标题、摘要、文档类型和 Markdown source。实现页还要登记能够定位职责的 canonical_paths；这让文档可以在启动编译阶段发现“文档声称存在的代码已经移动或删除”。

文档清单必须显式声明公开可见性。公共技术文档可匿名读取，但这不意味着业务任务、因子源码或研究文件也公开；业务对象仍由各自的访问控制判断。

## 内容规则 {#content-rules}

- 所有二级及更低标题使用稳定小写短横线 anchor；链接不能依赖会变化的标题文本。
- 使用普通 Markdown，不嵌入 HTML、脚本、远程图片或不可审计的 iframe。
- 内链使用 `/docs/<slug>`，跨页跳转时附带稳定 fragment；外链只使用 HTTPS 或 HTTP 权威来源。
- 代码入口只写当前实现中可定位的路径；如果某功能已经迁移，不保留“兼容性”文字来暗示旧入口仍受支持。
- 说明默认值、权限或数据保留时，区分“当前代码行为”“建议控制”和“组织需要另行确定的政策”。

## 编译与公开读取 {#compile-read}

Manager 启动时读取清单、解析 Markdown、校验路径和内链，并把安全渲染后的页面目录放入内存。读取请求只访问这个编译结果，不在每次请求时扫描磁盘或重新解释 Markdown。

前端先读取目录，再在选中页面时获取正文。目录和正文都有短期缓存，但 revision 改变后客户端必须重新获取；缓存不能成为绕过权限或继续展示已撤销内容的手段。

## 新增页面流程 {#add-page}

1. 先决定页面属于教程、操作指南、参考、概念、实现或排查哪一类。
2. 在对应语义目录创建中文 Markdown，并为每个标题指定稳定 anchor。
3. 在 manifest 登记页面，给实现页列出真实存在且正文中确实提到的 canonical_paths。
4. 为页面中的每个内链核对目标 slug 和 anchor，避免链接到废弃页面。
5. 运行文档、公开访问和容器打包测试，再检查渲染后的手机布局。
6. 只有随版本发布后，用户才应把页面当作当前公开契约。

## 发布检查表 {#publication-checklist}

发布前应确认：页面内容是中文且术语与 UI 一致；没有秘密、私有路径或未验证承诺；字段类型、默认值、权限和错误含义来自当前代码或明确标注为建议；实现页的路径没有漂移；匿名访问只覆盖文档；移动端首屏不会下载全部正文和大文件。

## 维护与废弃 {#maintenance-deprecation}

修改接口、字段或存储边界时，先更新实现和测试，再同步更新文档。被废弃的入口应在 ADR 或变更记录中说明迁移目标和停止时间；公开参考页不应继续给出可复制的旧命令。
