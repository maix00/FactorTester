## 字段清单从哪里来 {#field-catalog}

本页的表格不是手工维护的副本。它由当前测试模块的后端注册表生成，覆盖可复用设置字段和提交级运行字段；每行同时带有测试类型、字段身份、字段路径、模块归属、中文标签、所在 tab、值类型、基数、作用域和注册默认值。

字段注册表是 UI、CLI、preview、RunSpec 冻结和执行解析共用的契约来源。代码变更后，字段清单会随 Manager 的新版本重新生成；文档 API 的 schema 版本和目录 revision 可用于判断客户端缓存是否需要更新。表格的客户端筛选只是同一注册契约的 Web、Swift、CLI 投影，不会复制三套字段定义。

## 为什么不是每个前端和框架各有一张表 {#catalog-boundary}

不应为 Web、Swift、CLI、Manager 内部框架和每个测试模块分别抄一张“全字段表”。这些层的职责不同：后端注册表拥有字段语义和默认值，客户端负责编辑和呈现，API 负责传输，执行器负责冻结和解析。重复表格会让标签、类型或默认值在某一层悄悄漂移。

当前采用一个字段参考页、多个可筛选视图：

| 契约范围 | 权威来源 | 公开呈现 | 是否独立字段页 |
| --- | --- | --- | --- |
| 测试设置与提交级运行字段 | 测试设置注册表 | 本页可换页表格，按测试类型、角色和客户端筛选 | 是，一个公共参考页 |
| Web、Swift、CLI 的投影差异 | 同一注册表的 client projection | 本页“客户端契约”筛选及字段路径 | 否，不复制字段 |
| Manager API 请求与响应 | API 路由/序列化契约 | [API 与 CLI 参考](/docs/api-cli-reference#factor-product-library)；需要机器校验时使用接口 schema | 仅在形成独立稳定 API 契约时增加 |
| 结果、生成物和 Evidence | 结果投影与 Evidence 契约 | 结果阅读和研究证据文档 | 按生命周期单独说明，不混入配置字段表 |
| UI 临时状态、布局和内部框架状态 | 客户端实现 | 实现架构与操作说明 | 否，不作为用户可提交字段 |

因此，“所有字段”指对用户可提交、会被冻结或会影响执行的公共业务字段；不是把每个内部变量、DOM 状态或框架私有属性都公开成字段。新增测试类型时，应把它注册到同一目录；只有当它拥有独立生命周期（例如结果生成物 schema）时，才新增对应的参考页。

## 如何阅读表格 {#read-field-table}

下方表格使用公共可换页表格部件。首屏只请求当前页的字段摘要，按测试类型、字段角色或关键字筛选时由服务端重新筛选；点击“下一页”不会改变字段定义，只改变返回窗口。

客户端筛选默认显示 Web 投影，也可切换 Swift 或 CLI。它用于审计三种调用面的可用字段差异；后端仍只维护一份注册定义。字段数量、排序和页面窗口由接口返回，前端不预取其余页。

“设置”字段属于可编辑测试配置或配置组；“运行”字段属于一次提交的身份、保留范围、输出或执行控制。默认值列是注册值，不代表所有条件下的实际生效值；实际运行仍要查看对应 Job 的冻结 RunSpec。

## 类型和默认值的解释 {#types-defaults}

值类型描述 JSON 层面的契约，例如 boolean、integer、number、string、date、time、duration、enum、reference、object 或 array。基数说明是单值还是多值；枚举候选、最小值、最大值、单位和条件规则在字段详情数据中保留。

默认值必须结合适用性阅读：可能是直接注册默认、依赖其他字段的条件默认、运行时派生值，或“不适用而省略”。预览和真实执行应使用同一解析结果；若某字段在 auto 模式下因产品、数据源或历史事件发生解析，应在任务详情和摘要中显示最终值及原因。

## 机器读取入口 {#machine-endpoint}

```text
GET /api/docs/test-fields?page=1&page_size=20
GET /api/docs/test-fields?application=ic_test&role=setting
GET /api/docs/test-fields?query=fee
GET /api/docs/test-fields?client=swift&page=1&page_size=20
```

接口返回 `client`、`total`、`page`、`page_size`、`clients`、`applications` 和 `fields`；字段行中的 `field_path` 用于区分设置字段与运行字段。它是公开的字段参考，不授予提交任务、查看私有对象或下载生成物的权限。

## 发现不一致时怎么处理 {#inconsistency}

如果 UI 标签、CLI 帮助、preview、任务详情和本页的字段契约不一致，应优先以当前后端注册和实际冻结 RunSpec 做证据比对。修复顺序应是统一注册与解析 helper，再更新客户端投影和测试；不要在某一个页面单独加一套默认值或字段别名。
